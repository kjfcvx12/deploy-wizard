# 배포 전 비용 확인 — 웹 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 웹 분석 화면에서 배포 직전에 만들어지는 리소스·구성 요소별 가격·기간별 금액을 보여 주고, 사용자가 사양(CPU·메모리)·예정 사용 시간·자동 증설 설정을 고른 뒤 그 옵션으로 배포하게 한다. 배포 상세·설정에서 사양과 사용 계획을 보고 예정 시간을 바꿀 수 있고, 알림 설정 화면이 새 알림 종류 `plan_exceeded`를 알게 한다.

**Architecture:** 서버 계산은 이미 있다 (`/api/pricing/options`, `/api/pricing/estimate`, 확장된 `Advice_Cost`, 배포 생성·`PATCH settings`의 새 항목). 화면은 `features/pricing/ui/`에 API 호출(`api.js`)·순수 로직(`costLogic.js`, `node:test`로 시험)·표시(`CostPanel.jsx`)를 두고 `AdvicePanel`이 쓴다. 가격 숫자는 JS 에 적지 않는다 — 전부 서버 응답이다.

**Tech Stack:** React 19, Vite, react-router, `node --test`(`tests/web/*.test.js`, `npm run test:web`), 앱 상수 파일(`app/src/ops/constants.js`)의 jest.

**Spec:** `docs/superpowers/specs/2026-11-16-cost-confirm-design.md` §5.5 (실행자는 둘 다 읽는다). 백엔드 계획: `docs/superpowers/plans/2026-11-16-cost-backend.md` (병합 완료, `test` 34e3695).

## Global Constraints

- 브랜치 `feat/cost-web` (`test`에서). 끝나면 `test`에 `--no-ff` 로컬 병합. push·`main`은 소유자의 명시적 허락 후에만.
- 화면 규칙 (`docs/conventions.md` "화면" 절을 먼저 읽는다): 위치 `features/<기능>/ui/`, 컴포넌트 `PascalCase.jsx`, 그 외 `camelCase.js`, 서버 호출은 기능마다 `ui/api.js`, **서버 필드 이름을 그대로** 쓴다(camelCase 변환 금지), 색·간격은 `shared/ui/styles.css`의 CSS 변수만(컴포넌트에 색 하드코딩 금지), 상태값 문자열은 상수 파일에서만, 폴링·비동기는 `alive` 플래그와 정리, **글이 잘리거나 숨겨지지 않게**(line-clamp·text-overflow·overflow:hidden 으로 내용을 가리지 않는다. 가로 넘침 없음: 320/375/390/768/1280px), 한글은 어절 단위로 줄바꿈(`body`의 `word-break: keep-all`, 긴 ARN 등은 `overflow-wrap`).
- **가격·금액 숫자를 JS 소스에 상수로 적지 않는다.** 표시 형식(`$`, 소수 자릿수)만 코드에 있다: 시간당은 소수 4자리, 기간·월 금액은 소수 2자리, 통화는 응답의 `currency`.
- 서버가 이미 하는 검증을 화면이 대신하지 않는다. 화면은 **같은 규칙으로 미리 안내**(입력 칸 옆 힌트·버튼 비활성)만 하고, 서버의 400 은 그대로 한국어로 보여 준다. 클라이언트 검증 규칙은 서버와 같아야 한다: 예정 시간 `0 < h <= 8760`, 증설은 최소·최대·기준·목표값 모두 또는 모두 없음, `1 <= 최소 <= 최대 <= 상한`, 목표값은 CPU·메모리 기준 1~100, 요청 수 기준 1~100000, 사양은 서버가 준 프리셋 목록 안에서만.
- 앱(Expo) 화면은 이번 계획 밖이다 — 단, Task 1 처럼 **상수 목록이 서버와 어긋나 동작이 깨지는 곳**만 맞춘다.
- 테스트: 순수 로직은 `tests/web/*.test.js`(node:test)로, 화면은 빌드(`npm run build`)와 실제 브라우저 확인(마지막 Task, 컨트롤러가 수행)으로. 전체 백엔드 테스트는 서버 코드를 바꾼 Task 2 에서만 `tests/test_pricing.py` 범위로. 동시에 테스트 러너를 두 번 돌리지 않는다.
- 소유자 지시: 질문은 `AskUserQuestion`으로만. 실제 AWS 비용이 드는 배포 버튼 클릭은 하지 않는다(분석은 읽기 전용이라 해도 된다).

## Review Focus

1. 옵션을 빠르게 바꿀 때 **낡은 추정 응답이 새 선택을 덮어쓰지 않는가** (요청 번호), 컴포넌트가 사라진 뒤 상태 갱신이 없는가 (`alive`).
2. 배포 요청 본문에 옵션이 **고른 것만** 실리는가 (고르지 않으면 `cpu`/`memory`/증설/`planned_hours`가 아예 없음 — 기본 동작 유지), 분석 후 입력이 바뀌면 옵션과 추정이 같이 지워지는가.
3. 가격을 못 가져올 때(503)·잘못된 옵션(400)·서버 꺼짐에서 화면이 깨지지 않고 한국어 안내 + 배포 버튼이 "금액 없이 배포"임을 분명히 하는가 (요금이 계속 나온다는 문구는 항상).
4. 숫자 입력: 빈 칸, 0, 음수, 소수, 아주 큰 수, `e` 표기, 붙여넣은 문자 → NaN·`Infinity`가 서버로 가지 않는가.
5. 320px 에서 구성 요소 표·옵션 줄이 가로로 넘치거나 잘리지 않는가, 접근성(라벨·`aria-live` 추정 갱신 안내·포커스).
6. 알림 종류 목록이 서버와 같아 설정을 토글해도 `plan_exceeded`가 빠지지 않는가.
