# 로컬 MCP 서버 (1단계) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code/Desktop이 배포 마법사의 REST API를 도구(읽기 8개, 행동 5개)로 부르게 하는 로컬 stdio MCP 서버를 만든다. 행동 도구는 미리보기 + 1회용 확인 토큰을 거친다.

**Architecture:** `features/mcp/`에 REST 클라이언트(`client.py`), 도구 로직(`services.py`), 허용 필드 스키마(`scheme.py`), MCP 등록·진입점(`server.py`)을 둔다. 서버 코드(DB·AWS)를 import하지 않고 HTTP로만 부른다. 2단계(로그인)에서는 `WIZARD_API_TOKEN` 머리말만 채우면 된다.

**Tech Stack:** Python 3.12, 공식 `mcp` SDK(Task 1에서 버전 확정), `httpx`(이미 있음), pytest(`httpx.MockTransport`, `ASGITransport`).

**Spec:** `docs/superpowers/specs/2026-11-16-mcp-design.md` (실행자는 둘 다 읽는다. 설계서 5.x = 이 계획의 근거)

## Global Constraints

- 브랜치 `feat/mcp-local` (`test`에서). 끝나면 `test`에 로컬 병합. push·`main`은 소유자의 명시적 허락 후에만.
- 새 AWS 호출·Express API 금지(Hard rule 2). MCP는 REST만 부른다. `features/mcp/`는 `features.deploys` 등 서버 모듈을 import하지 않는다 (**예외: 테스트만** `PROGRESS_STATUSES` 비교용 import).
- 이름: 클래스 Pascal_Snake(`Mcp_Service`, `Wizard_Client`, `Confirm_Store`), 함수 `<계층>_<도메인>_<동작>`(`services_mcp_deploy`, `client_logs_tail`), 함수 위 한 줄 한국어 주석, docstring 없음, 기존 `=` 공백 유지, 사용자에게 보이는 문자열은 한국어.
- 서비스는 `@staticmethod` 클래스. 첫 인자는 `client: Wizard_Client`(DB·AWS 아님).
- **stdio 서버는 stdout에 아무것도 출력하면 안 된다** (프로토콜이 깨진다). 로그는 stderr.
- 도구 결과의 에러·로그·`explain`은 `shared.masking.mask_text`를 통과하고, 길이를 자르고, "데이터" 머리말로 감싼다.
- `role_arn`은 어떤 결과에도 싣지 않는다. AWS 계정 ID는 끝 4자리만(`****1234`).
- 설정(`shared/settings.py`, `Field(기본값, alias=...)`): `wizard_api_url`(`WIZARD_API_URL`, 기본 `http://localhost:8081`), `wizard_api_token`(`WIZARD_API_TOKEN`, 기본 None), `mcp_max_live_deploys`(`MCP_MAX_LIVE_DEPLOYS`, 3), `mcp_confirm_ttl_seconds`(`MCP_CONFIRM_TTL_SECONDS`, 300).
- 테스트는 AWS·Docker·실제 서버 없이 `pytest`로. 동시에 pytest를 두 번 돌리지 않는다. 전체 실행은 마지막 Task에서 한 번.
- 소유자 지시: 질문은 `AskUserQuestion`으로만. 실제 AWS 비용이 드는 Task 7의 실행 전에는 반드시 다시 묻는다.

## Review Focus

1. 로그가 500줄을 넘을 때 `tail=N`이 **마지막** N줄을 주는가 (API는 `after` 기준 첫 500줄만 준다) → Task 2.
2. 로그·에러 문자열 안의 "이전 지시를 무시하라" 문구와 토큰 모양 문자열(`ghs_…`, `AKIA…`) → Task 3.
3. 확인 토큰의 재사용, 다른 인자로 사용, 만료 → Task 3, 5.
4. 서버가 꺼져 있을 때·422·409·404 → Task 2.
5. `wait_for_deploy`가 상한 120초를 넘지 않고, 처음 보는 상태 값에서도 끝나는가 → Task 4.
6. stdout 오염: 서비스를 돌려도 stdout이 비어 있는가 → Task 6.

### Task 5: 행동 도구 로직 (미리보기 → 확인 → 실행)

**Files:**
- Modify: `features/mcp/services.py`
- Test: `tests/test_mcp.py`

**Interfaces:**
- Consumes: Task 3 `Confirm_Store`, Task 4 `LIVE_STATUSES`, `services_mcp_analyze/get_deploy/connections`.
- Produces (`Mcp_Service`, `@staticmethod async`, 첫 인자 `client`, 둘째 `store: Confirm_Store`):
  - `services_mcp_deploy(client, store, repo_url: str, branch: str | None = None, connection_id: int | None = None, confirm_token: str | None = None, max_live: int = 3) -> dict`
  - `services_mcp_redeploy / services_mcp_stop / services_mcp_start / services_mcp_delete(client, store, d_id: int, confirm_token: str | None = None) -> dict`
- 규약:
  - `confirm_token` 없음 → **실행하지 않고** `{"status": "confirmation_required", "action": <tool 이름>, "summary": str, "warnings": list[str], "confirm_token": str, "expires_in_seconds": int, "instruction": "사용자에게 이 내용을 보여 주고 명시적으로 승인을 받은 뒤에만 같은 도구를 confirm_token과 함께 다시 부르세요"}`.
  - `confirm_token` 있음 → `store_consume(token, tool, args)`가 True면 실행하고 `{"status": "done", ...요약}`, False면 `Wizard_Error("확인 토큰이 없거나 만료됐거나 이미 썼습니다. 미리보기부터 다시 하세요")`.
  - `args` = 토큰에 묶는 인자 dict (`deploy`: `repo_url, branch, connection_id`; 나머지: `d_id`).
  - `deploy`: `connection_id`가 있으면 `GET /api/accounts/connections`에서 찾아 `aws_account_id = aws.a_id`(AWS `status`가 `verified`가 아니면 `Wizard_Error("AWS 연결이 아직 확인되지 않았습니다 …")`), `github_installation_id = github.g_id`(없으면 None, public만)를 `POST /api/deploys`에 싣는다. 없는 `connection_id`는 `Wizard_Error`. 미리보기에는 분석 결과(언어·추천 사양·예상 비용 문구)와 "ECR·ECS 서비스·ALB가 만들어지고 떠 있는 동안 요금이 계속 나옵니다"가 들어간다. 살아 있는 배포 수(`LIVE_STATUSES`)가 `max_live` 이상이면 미리보기 단계에서 `Wizard_Error`(한도 안내, 먼저 멈춤/삭제하라는 말 포함) — 확인 단계에서도 다시 검사한다.
