# 요구사항

## 1. 목적

GitHub 주소 하나와 사용자의 AWS 임시 권한으로 앱을 ECS Express Mode에 배포하고, 운영 중 문제가 생기면 스스로 복구하며, 원인과 수정할 곳을 알려 주는 서비스를 **웹과 모바일 앱** 양쪽에서 쓰게 한다.

## 2. 사용자

| 구분 | 설명 |
|---|---|
| 일반 사용자 | 자기 AWS 계정과 GitHub를 연결해 레포를 배포하는 사람. 인프라 지식이 깊지 않다. Google 계정으로 로그인한다 |
| 운영자 | 서비스를 운영하는 사람(현재 사용자 본인). 서버, GitHub App, 발송 서비스를 관리한다 |

## 3. 범위

**이번 확장의 범위**: 앱 화면, 웹 화면 정리, 운영 감시와 자동 복구, 알림(메일·푸시), Google 로그인, 사용자별 데이터 분리.

**범위 밖 (별도 프로젝트로 순서를 정한다)**: 격리된 빌더(남의 코드를 내 PC가 아닌 곳에서 빌드), 결제와 사용량 한도, RDS 자동 생성(M7), 프론트+백 동시 배포(M8), 학습 모드(M10), 갤러리(M11).

## 4. 단계

사용자가 정한 순서: 기능을 먼저 만들고 로그인은 뒤에 붙인다.

| 단계 | 내용 | 로그인 |
|---|---|---|
| 1. 화면 | 웹 반응형 정리 + 앱(Expo) 화면. 지금 API 그대로 | 없음 (로컬, 한 사용자) |
| 2. 운영 | 상태 감시, 인시던트, 자동 복구, 원인 설명, 메일·푸시 알림 | 없음. 알림 메일은 `.env` 주소 한 곳 `[가정]` |
| 3. 로그인 | Google 로그인, `users`, 모든 데이터에 `u_id` 적용 | 적용 |
| 4. 상용 준비 | 서버 공개(HTTPS), 사용자별 격리 검증, 격리 빌더, 한도 | 적용 |
| 5. 스토어 | 개발자 계정, 심사 자료, 정식 출시 | 적용 |

1~2단계에서 `u_id` 컬럼은 **nullable로 미리 넣고**, 서비스 코드는 "현재 사용자" 한 곳(의존성 함수)을 거쳐 데이터를 읽게 만든다. 3단계에서 그 함수만 실제 로그인으로 바꾸면 되게 한다.

| FR-05 | 이상을 감지하면 인시던트를 만들고 원인을 모은다 | 2 |
| FR-06 | 재시작과 이전 버전으로 되돌리기는 확인 없이 자동으로 실행한다 `[가정: 이 둘만]` | 2 |
| FR-07 | 자동 복구 결과와 관계없이, 원인과 수정할 곳을 한국어로 메일과 앱 알림으로 보낸다 | 2 |
| FR-08 | 알림은 앱 안의 알림 목록에도 남고, 읽음 처리를 할 수 있다 | 2 |
| FR-09 | 사용자는 배포마다 자동 복구를 끌 수 있다 `[가정]` | 2 |
| FR-10 | Google 계정으로 로그인하고, 로그아웃하고, 계정을 삭제할 수 있다 | 3 |
| FR-11 | 사용자는 자기 데이터(배포, 연결, 알림)만 볼 수 있다 | 3 |
| FR-12 | 앱은 푸시 알림을 누르면 해당 인시던트 화면으로 바로 이동한다 | 2 |
| FR-13 | GitHub 앱 설치와 AWS 연결을 앱에서도 끝낼 수 있다 (앱 안 브라우저, 딥링크) | 1 |
| FR-14 | 마법사는 소스에서 환경변수 **이름**을 찾아 사용자에게 보여 주고, 사용자가 값을 입력한다. 시크릿 파일은 읽지 않는다 | 1 |
| FR-15 | 환경변수 값은 응답, 로그, AI, 알림에 나가지 않고, 시크릿 값은 우리 DB에 평문으로 저장하지 않는다 | 1 |
| FR-16 | 값이 없는 필수 환경변수가 있으면 `deploying` 직전에 멈추고 입력을 요청한다. 입력 뒤 이어서 배포한다 | 1 |
| FR-17 | 이름을 놓쳐 앱이 죽으면, 실패 해설이 빠진 변수 이름을 찾아 입력 화면으로 안내한다 | 1 |
| FR-18 | 배포 전에 레포를 읽기만 해서 추천 사양 수준(small/medium/large), 필요한 것, 비용 **범위**, 확신도를 알려 준다 | 1 |
| FR-19 | 추천 판정은 코드(규칙)가 하고, AI는 판정을 고르지 않는다. 비용은 기준일이 적힌 단가표로 계산하고 "추정"임을 표시한다 | 1 |
| FR-20 | 지원하지 않는 필요 항목(DB 자동 생성, 워커 등)은 "아직 만들어 주지 못함"이라고 알린다 | 1 |
| FR-21 | 사용자는 추천을 쓰거나 다른 수준을 골라 배포하고, 고른 값이 저장된다 | 1 |
| FR-22 | 배포 주인이 직접 켠 서비스만 갤러리에 올라가고, 로그인한 사용자가 댓글·개선 제안을 쓸 수 있다. 신고와 임시 숨김이 있다 (`07`) | 4 |
| FR-23 | 의견이 5개 쌓이거나 7일이 지나면(먼저 오는 쪽) 요약과 개선 추천을 만들어 주인에게 메일과 앱 알림으로 보낸다. 추천은 글로만 하고 코드를 고치지 않는다 | 4 |
| FR-24 | 무료는 배포 1개의 운영·복구를 약 3개월 해 주고, 끝나면 서비스는 그대로 두고 운영·복구만 멈춘다 (자동 삭제 없음) | 4 |
| FR-25 | 유료는 구독으로 운영·복구를 이어 가고, 무료 만료 14일 전부터 안내한다 | 4 |

## 6. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-01 보안 | 토큰·비밀값은 로그, DB, AI, 메일, 푸시 본문에 평문으로 나가지 않는다 (`mask_text`). 규칙 6 |
| NFR-02 보안 | 다른 사용자의 리소스는 존재 여부도 드러내지 않는다 (403이 아니라 404) |
| NFR-03 보안 | 인증 토큰은 앱에서 보안 저장소(Keychain/Keystore), 웹에서 httpOnly 쿠키 `[가정]` |
| NFR-04 보안 | 웹훅은 서명 검증 필수 (이미 구현) |
| NFR-05 비용 | 감시 요청과 알림은 사용자 AWS 비용을 늘리지 않는다. 감시는 공개 주소 GET 위주로 한다 |
| NFR-06 안정 | 감시·복구·알림 중 하나가 실패해도 다른 배포와 서버 전체는 계속 돈다 |
| NFR-07 안전 | 배포 파이프라인에서 AI는 정해진 스키마의 빈칸만 채운다 (규칙 4). **운영·복구에서만** 에이전트가 도구를 고를 수 있고(D12), 행동 도구는 코드가 다시 검문하며 삭제·사양 변경 도구는 주지 않는다. 사용자 앱의 로그는 믿지 않는 입력이다 |
| NFR-08 호환 | 앱은 iOS와 Android 모두. 웹은 최신 브라우저와 폰 폭 |
| NFR-09 언어 | 사용자에게 보이는 모든 문구는 한국어 |
| NFR-10 확인 | 만들기·바꾸기·지우기는 확인 단계를 거친다. 열린 질문 대신 버튼 2~3개 (규칙 3) |

## 7. 제약 (CLAUDE.md 하드 규칙에서)

- AWS 세션은 주입한다. 전역 클라이언트 금지.
- **Express Mode의 새 호출을 지어내지 않는다.** 재시작과 되돌리기는 `docs/aws-notes.md`에 검증된 호출(서비스 갱신 = 이미지 교체)로만 구현한다. 검증이 안 되면 그 행동은 자동 목록에서 뺀다.
- 우리가 만든 AWS 리소스에만 `managed-by: deploy-wizard` 태그를 달고, 정리는 태그된 것만 한다.
- 외부 명령은 `proc_run` 리스트 인자.
- API를 바꾸면 `docs/api-spec.md`, 상태값을 바꾸면 세 곳을 같이 고친다.

## 9. 스토어 출시 준비물 (5단계, 지금은 만들지 않는다)

- Apple 개발자 계정(연 99달러), Google Play 개발자 계정(1회 25달러)
- 개인정보 처리방침과 이용약관 공개 주소
- 앱 안 계정 삭제 기능 (FR-10에 포함)
- 로그인은 **Google만** (2026-11-09 결정). iOS 는 2026-11-16 에 빠졌다. iOS 를 다시 넣을 때 외부 로그인 앱에 추가 로그인 옵션을 요구하는지는 **규정을 확인하지 않았다.** 이 단계 전에 공식 문서로 확인하고, 필요하면 그때 다시 정한다
- 앱 아이콘, 스크린샷, 설명문
