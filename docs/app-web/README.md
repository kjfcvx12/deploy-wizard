## 구현 상태

- **계획 A (백엔드: 환경변수 감지·입력 + 배포 전 분석) - 구현됨** (2026-11-09, 브랜치 `feat/backend-env-advice`). 계획: [`../superpowers/plans/2026-11-09-backend-env-and-advice.md`](../superpowers/plans/2026-11-09-backend-env-and-advice.md). API는 `docs/api-spec.md`의 "Env"·"Advice", 구조는 `docs/architecture.md`로 옮겼다. 시크릿 값 저장(D8)과 사양 숫자·비용(D10)은 검증 전이라 아직 없고, 실제 AWS 배포로는 확인하지 않았다.
- **계획 B (웹 화면: 환경변수 입력 카드 S-19 + 배포 전 분석 두 단계 S-20) - 구현됨** (2026-11-09, 브랜치 `feat/web-env-advice`). 계획: [`../superpowers/plans/2026-11-09-web-env-and-advice-ui.md`](../superpowers/plans/2026-11-09-web-env-and-advice-ui.md). 화면 설명은 `docs/ui-spec.md`로 옮겼다. 수준 선택 UI(`size_tier` 없음, D10)와 시크릿 값 입력(D8)은 만들지 않았다. 확인은 빌드와 모의 API를 쓴 브라우저 점검뿐이고 실제 백엔드·AWS로는 해 보지 않았다.
- **계획 C1 (Expo 앱 핵심: 배포 목록, 새 배포 두 단계, 배포 상세, 환경변수 입력 카드) - 구현됨** (2026-11-09, 브랜치 `feat/expo-app-core`, 합치는 것은 나중에). 계획: [`../superpowers/plans/2026-11-09-expo-app-core.md`](../superpowers/plans/2026-11-09-expo-app-core.md). 코드는 `app/`(Expo SDK 58, Expo Router, 순수 JS)이고 설명은 `app/README.md`, 화면 규칙은 `docs/ui-spec.md`의 "앱". 기능명세서의 C-01~C-12(목록, 새 배포, 진행·로그·해설·이력, 다시 배포·멈춤·다시 켜기·삭제), H(환경변수 입력), I(배포 전 분석)를 앱에 옮겼다. **C1 에 없는 것**: 연결 관리와 연결 흐름(B-01~B-07: AWS·GitHub 연결 만들기, 앱 안 브라우저, 딥링크), 푸시 알림(E), 장애 화면(D), 로그인(A), 설정, 스토어 빌드(EAS). 앱 이름과 번들 ID는 임시값이다(D6). 인증 코드는 없고 서버 주소는 `EXPO_PUBLIC_API_BASE_URL`로 넣는다. 확인은 `npx jest`(211개)와 웹 번들 내보내기, 모의 API 로 돌린 Playwright(웹 번들 390×844 라이트·다크)뿐이다. **실제 iOS·안드로이드 기기나 에뮬레이터에서는 한 번도 돌려 보지 않았고**, 실제 백엔드·AWS 로도 해 보지 않았다. 웹 번들 확인은 실제 앱 동작의 대용품이다.
- 나머지(운영 비서, 로그인, 앱 등)는 아직 구현하지 않았다. 기존 화면(목록·상세·계정)의 좁은 화면 정리는 구현했다 (2026-11-09, 브랜치 `feat/responsive-existing`, 합치는 것은 나중에). 규칙과 확인 범위는 `docs/ui-spec.md`의 "반응형" 절.

## 사용자가 정한 것 (대화에서)

- 상용 서비스. 여러 사용자가 Google 로그인으로 각자 쓴다.
- 앱은 스토어에서 받아 설치하는 앱이고, 나중에 실제 스토어에 올린다.
- 앱은 웹과 **모든 기능이 같은 상태**여야 한다.
- 로그인은 기능 작업이 어느 정도 끝난 뒤에 붙인다.
- 문제가 생기면 마법사가 자동으로 해결한다. 재시작은 확인 없이 해도 된다.
- 문제가 생기면 **왜 생겼는지, 어디를 고쳐야 하는지**를 메일과 앱 알림으로 보낸다.

## 규칙 수정 (2026-11-09 사용자 결정, 반영함)

자동 복구는 CLAUDE.md 규칙 3 ("자동으로 하는 건 되돌리기 하나")과 부딪혀서, 사용자가 규칙을 고치라고 했다. `CLAUDE.md` 규칙 3과 `docs/architecture.md`의 자동화 원칙을 고쳤다. 자동으로 하는 것은 **재배포 실패 되돌리기**와 **운영 복구(재시작, 이전 정상 버전으로 되돌리기)** 두 가지다. 사양 변경·확장·삭제는 계속 확인을 받는다.

## 로그인은 Google만 (2026-11-09 사용자 결정)

지금은 Google 로그인만 만든다. Apple 로그인 등 다른 로그인은 만들지 않는다. iOS 스토어 심사에서 다른 로그인 옵션을 요구하는지는 5단계(스토어) 전에 공식 문서로 확인하고, 그때 필요하면 다시 정한다.
