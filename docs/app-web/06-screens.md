# 화면 목록과 와이어프레임 지침

피그마에 옮길 입력이다. 화면 ID(S-xx)는 피그마 프레임 이름으로 그대로 쓴다. 기능 ID는 [02-feature-spec.md](./02-feature-spec.md)를 가리킨다.

## 1. 디자인 기준

| 항목 | 기준 |
|---|---|
| 기존 토큰 | `shared/ui/styles.css`의 `--bg --surface --surface-2 --border --text --muted --accent --ok --warn --err --term-bg --term-text --radius --mono`를 피그마 변수로 그대로 옮긴다. 라이트/다크 두 모드 |
| 상태 배지 | `running` ok · `failed` err · 진행 중 accent(점 깜빡임) · 그 외 muted · `stopped` muted |
| 프레임 크기 | 앱 390×844 (iPhone 14), 웹 데스크톱 1280, 웹 모바일 390 |
| 터치 | 눌리는 것의 최소 높이 44px |
| 글꼴 | 본문 시스템 글꼴, 코드·로그 고정폭 |
| 문구 | 한국어. 서버의 `detail`을 그대로 보여 주는 자리를 따로 둔다 |
| 파괴적 동작 | 빨간 테두리 + 확인 대화상자, 기본 포커스는 안전한 쪽 |
| 묻는 방식 | 버튼 2~3개. 열린 입력창으로 묻지 않는다 |

## 3. 앱 내비게이션

하단 탭 4개. 상세 화면은 탭 위에 쌓인다 (뒤로 가기).

| 탭 | 화면 | 뱃지 |
|---|---|---|
| 배포 | S-02 → S-04 → S-05, S-06, S-07, S-13 | 문제가 있는 배포 수 |
| 알림 | S-12 → S-13 | 읽지 않은 수 |
| 연결 | S-08 → S-09, S-10, S-11 | 업데이트 필요 시 점 |
| 내 정보 | S-15 | |

웹은 같은 구조를 상단 내비게이션(배포 · 알림 · 계정 연결 · 내 정보)으로 둔다.

## 4. 화면별 구성 (위에서 아래로)

### S-02 배포 목록
1. 헤더: 제목, [＋ 새 배포]
2. 문제 배너 (열린 인시던트가 있을 때만): "my-api에 문제가 있습니다 · 자동 복구 중" → S-13
3. 배포 카드 목록: 레포명 · `#번호 · 브랜치 · 언어` · 상태 배지 · 헬스 점
4. 빈 상태: "아직 배포가 없습니다. 연결을 확인하고 첫 배포를 만들어 보세요" + [＋ 새 배포] (연결이 없으면 [계정 연결하기])

### S-03 새 배포
1. 연결 블록 선택 (블록이 하나뿐이면 숨김)
2. GitHub 주소 입력 + 레포 목록 (public/private 표시)
3. [브랜치 고르기] → 드롭다운 (기본 브랜치에 `(기본)`)
4. [배포] — 실패하면 서버 `detail`을 폼 아래에

### S-04 배포 상세
1. 머리: 레포, `#번호 · 브랜치 · 커밋 7자 · 언어 · 앱 폴더`, 배지(실험 지원, 자가수정 N회, 상태)
2. 단계 진행 막대 (지난 단계 초록, 현재 파랑, 실패 빨강)
3. 주소 카드(`running`): HTTPS 주소 [열기] [복사], 헬스 배지, 요금 안내 한 줄
4. 인시던트 카드(열린 것이 있을 때): 한 줄 요약 → S-13
5. 해설 카드(`failed`) → S-06
6. 로그 미리보기 마지막 몇 줄 → S-05
7. Dockerfile (접힘)
8. 문제 이력 (접힘) → S-07
9. 동작 버튼: `running` [다시 배포] [멈춤] [삭제] · `stopped` [다시 켜기] [삭제] · [설정] → S-14

### S-20 분석 결과·추천
S-03(새 배포)에서 [분석]을 누르면 이 화면으로 온다.
1. 레포 이름, 언어·지원 수준 배지(공식/실험), 앱 폴더
2. **추천 수준** 큰 카드: `small/medium/large` + 확신도 배지(`낮음`이면 주황으로 "추정입니다")
3. **왜 이렇게 추천했나**: 근거 문장 목록 (예: "pandas를 사용해 메모리를 넉넉히 잡았습니다")
4. **예상 비용**: 범위, 기준일, "트래픽에 따라 늘어납니다". 숫자를 아직 계산할 수 없으면 "아직 계산할 수 없습니다" 한 줄
5. **필요한 것**: 항목마다 아이콘 + 한 줄. 지원하지 않는 것은 회색 + "아직 만들어 주지 못합니다"
6. **알 수 없었던 것** (접힘)
7. 수준 선택 3칸(추천 표시), 하단 버튼 두세 개: [이 사양으로 배포] [다른 레포로] — 열린 질문 없음

### S-19 환경변수 입력
1. 안내 한 줄: "코드에서 필요한 값을 찾았습니다. 값은 이 화면에서만 입력하고, 한 번 저장하면 다시 보여 드리지 않습니다."
2. **꼭 필요해 보이는 것** 목록: 변수 이름(고정폭), 찾은 위치(`app/config.py:12`), 종류 배지, 입력창(시크릿은 가림 + 보기 토글 없음), [건너뛰기]
3. **종류를 모르는 것**: 버튼 선택 "데이터베이스 주소 / 외부 서비스 키 / 일반 설정 / 잘 모르겠음" (열린 질문 아님)
4. **기본값이 있어 비워도 되는 것** (접힘)
5. [변수 직접 추가]. 아래에 고정 문구: "자동으로 찾지 못한 변수가 있을 수 있습니다. 배포 후 앱이 시작하지 못하면 알려 드립니다."
6. 하단 [이어서 배포] (값 없는 필수 변수가 남아 있으면 비활성 + 이유 표시)
7. 배포가 이미 `running`일 때 값을 바꾸면 "다시 배포해야 적용됩니다" 배너 + [다시 배포]

앱은 한 화면에 변수 하나씩 넘기는 방식과 목록 방식 중 목록을 기본으로 하되 입력창이 키보드에 가리지 않게 한다.

### S-06 실패 해설 카드
한 문장 요약 → 원인 → 번호 매긴 조치 → (접힘) 원문 에러. 버튼 3개: [다시 배포] [만들어진 리소스 정리] [그대로 두기]. 안내문 "아무것도 누르지 않으면 그대로 둡니다".

### S-08 계정 연결
1. 제목 "계정 연결", [＋ 블록 추가] [블록 삭제]
2. 블록 카드 하나: 이름 + 상자 둘 (AWS, GitHub). 각 상자에 이름, 상태 배지, `‹ ›`로 계정 넘기기, [선택], 하단 [계정 추가] [연결 확인] [연결 해제]. 앱은 상자를 위아래로 쌓는다
3. 맨 아래: `‹ n / 전체 ›`, [선택]
4. 경고 띠: 스택 업데이트 필요, 남은 템플릿 파일

### S-10 AWS 연결 안내 (7단계)
스택 이름, `TrustedAwsAccountId`, `ExternalId`를 **값마다 [복사]**. 콘솔 열기 버튼, 단계마다 콘솔 화면을 단순하게 그린 그림, IAM 승인 체크, 출력 탭 위치, 역할 ARN 입력. 앱에서는 한 화면에 한 단계씩 넘기는 형태로 하고, 값은 계속 위쪽에 고정해서 보인다.

### S-12 알림 목록
읽지 않은 것은 굵게 + 점. 항목: 아이콘(종류), 제목, 한 줄 본문, 시각. 상단 [모두 읽음]. 항목을 누르면 S-13 또는 S-04. 빈 상태: "새 알림이 없습니다".

### S-13 인시던트 상세 (신규 핵심 화면)
1. 상태 배지: `open` 주황 · `recovering` accent · `resolved` ok · `needs_action` err
2. 한 줄 요약
3. **원인** (왜 생겼나)
4. **고칠 곳** (`fix_where`) — 파일 이름·설정 위치. 복사 가능한 고정폭 글자
5. **마법사가 한 일**: 시간순 세로 타임라인 (감지 → 재시작 → 결과 → 되돌리기 → 결과)
6. 헬스 이력 막대 (최근 24시간)
7. 버튼: `needs_action`이면 [다시 배포] [멈춤] [그대로 두기]. 나머지는 [배포 보기]

### S-14 배포 설정
스위치 둘: 새 커밋이 오면 자동 재배포 / 문제가 생기면 자동 복구. 설명 한 줄씩 ("자동 복구는 재시작과 이전 버전으로 되돌리기만 합니다"). 변경은 저장 버튼 없이 즉시 반영하되 토스트로 알린다.

### S-15 내 정보
Google 계정 정보, 알림 설정(메일, 푸시, 종류별), [로그아웃], [계정 삭제] (빨간 테두리, S-16).

### S-16 확인 대화상자
제목 → 무엇이 일어나는지 한 문장 → 되돌릴 수 없는지 → [취소](기본 포커스) / [실행](빨간). 예: "ECS 서비스와 ECR 이미지가 함께 지워집니다. 되돌릴 수 없습니다."

## 5. 상태별로 그려야 하는 변형

| 화면 | 변형 |
|---|---|
| S-02 | 빈 / 불러오는 중 / 목록 / 오류 / 오프라인 / 문제 배너 있음 |
| S-04 | `queued~deploying`(진행) / `running` / `failed` / `stopped` / 인시던트 있음 |
| S-08 | 블록 없음 / AWS만 / GitHub만 / 둘 다 / `invalid` / 업데이트 필요 |
| S-13 | `recovering` / `resolved` / `needs_action` |
| 공통 | 라이트/다크, 앱/웹 데스크톱/웹 모바일 |

## 6. 피그마 작업 순서 제안

1. 변수(토큰) + 상태 배지 + 버튼/카드/대화상자 컴포넌트
2. 앱: S-02, S-04, S-13, S-12 (핵심 4장) 먼저
3. 나머지 앱 화면
4. 웹 데스크톱 레이아웃 (앱 컴포넌트 재사용)

## 7. 피그마 연결 상태

이 세션에서는 Figma 연결이 **인증되지 않아** 파일을 만들지 못했다. 인증하면 위 목록을 입력으로 프레임을 만든다.
