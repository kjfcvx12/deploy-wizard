# UI 스펙

React 19 + Vite + react-router. 화면 코드는 각 기능의 `ui/`에 있고, `shared/ui/App.jsx`는 경로만 잇는다.

| 경로 | 화면 | 파일 |
|------|------|------|
| `/` | 새 배포 + 내 배포 목록 | `features/deploys/ui/DeployListPage.jsx` |
| `/deploys/:d_id` | 배포 상세 | `features/deploys/ui/DeployDetailPage.jsx` |
| `/accounts` | 계정 연결 (M6, AWS 절반만) | `features/accounts/ui/AccountsPage.jsx` |
| `/incidents/:i_id` | 인시던트 상세 (S-13, 계획 E) | `features/incidents/ui/IncidentDetailPage.jsx` |
| `/deploys/:d_id/settings` | 배포 설정 (S-14, 계획 E) | `features/deploys/ui/DeploySettingsPage.jsx` |
| `/notifications` | 알림 목록 (S-12, 계획 E) | `features/notifications/ui/NotificationsPage.jsx` |
| `/notification-settings` | 알림 설정 (S-15 알림 부분, 계획 E) | `features/notifications/ui/NotificationSettingsPage.jsx` |

운영 화면 네 개(아래 "4. 운영 화면")는 계획 E 에서 더했다. 상단 바에는 `알림`(안 읽은 수 알약) 링크가 `계정 연결` 앞에 붙는다 (`features/notifications/ui/BellLink.jsx`).

## 1. 목록 (`/`)

**새 배포** — 위에 연결 블록 드롭다운(`AccountPicker`, 연결이 있을 때만), 그 밑에 GitHub 주소 입력창.
- 주소 입력창은 직접 입력도, 목록에서 고르기도 된다(`<input list>` + `<datalist>`). GitHub가 살아 있는 블록을 고르면 `GET /api/accounts/github/{g_id}/repositories`로 그 계정이 읽을 수 있는 레포 주소를 받아 목록에 채운다(옆에 public/private). 목록을 못 불러와도 직접 입력은 된다.
- [브랜치 고르기]를 누르면 `GET /remote`로 목록을 받아 드롭다운으로 바뀐다. 기본 브랜치가 선택돼 있고 `(기본)` 표시.
- 고르지 않고 [분석]을 누르면 기본 브랜치를 분석한다. 배포는 분석 결과 패널의 [이 레포로 배포]로만 한다 (두 단계, 아래 "분석 결과 패널").
- (M6) 연결된 계정이 있으면 주소 입력창 위에 `AccountPicker`(블록 드롭다운, 기본은 "연결 안 함")가 나온다. GitHub 연결을 고르면 private 레포도 배포 가능. 연결이 하나도 없으면 이 영역 자체가 안 보인다.
- 배포가 만들어지면 상세 화면으로 이동. 분석이나 배포가 실패하면 서버의 `detail`을 보여 준다(분석 실패는 폼 카드 안, 패널이 떠 있는 채 배포가 실패하면 패널 아래).

**문제 배너** (계획 E) — `내 배포` 카드 위, 끝나지 않은 인시던트(`open_incident_id`)가 있는 배포마다 한 줄 `{레포}에 문제가 있습니다 · 자동 복구 중` (인시던트가 `needs_action`이거나 그 배포의 `auto_recover`가 꺼져 있으면 `... · 확인이 필요합니다`). 누르면 `/incidents/{id}`. 글은 `problemLabel`(`features/incidents/ui/constants.js`).

**내 배포** — 레포 이름, `#d_id · 브랜치 · 언어 · 주소`, 상태 배지. `running`이면 배지 왼쪽에 헬스 점(`HealthDot`: 초록 응답 정상 · 빨강 응답 없음 · 회색 확인 전, 접근성 라벨 `헬스체크: ...`, 모르는 값이나 값이 없는 옛 서버면 그리지 않는다).
- 진행 중인 배포가 있으면 3초, 없으면 15초마다 새로 읽는다.
- `env_pending > 0`이면 `#d_id · 브랜치 · 언어 · 주소` 줄 끝에 ` · 환경변수 N개 입력 필요`를 붙인다 (예: `환경변수 2개 입력 필요`). 좁은 화면에서는 줄이 바뀐다. 상태가 `needs_input`이면 배지는 "입력 필요"(주황, 실험 지원 배지와 같은 톤)이고, 진행 중이 아니므로 15초 간격으로 읽는다.

## 2. 상세 (`/deploys/:d_id`)

위에서부터:

1. **머리** — 레포, `#d_id · 브랜치 · 커밋(전체 40자, 줄바꿈) · 언어 · 앱 폴더`, 배지(실험 지원 / 자가수정 N회 / 상태)
2. **단계 진행** — 클론 → 판별 → Dockerfile → 빌드 → 푸시 → 배포 → 완료. 지난 단계 초록, 현재 단계 파랑(깜빡임), 실패한 단계 빨강
   - `needs_input`이면 푸시까지 초록, "배포" 칸이 주황 막대(`.step.wait`, 깜빡이지 않음)로 "기다리는 중"을 나타내고 완료 칸은 빈 채로 둔다.
3. **주소 카드** (`running`일 때) — 클릭 가능한 HTTPS 주소, 헬스 배지, 요금 안내 한 줄
4. **해설 카드** (`failed`일 때) — `features/explains/ui/ExplainCard.jsx`
   - 한 문장 요약 → 원인 → 번호 매긴 조치 → 원문 에러
   - 버튼: **[다시 배포]** · **[만들어진 리소스 정리]**(리소스가 있을 때만) · 안내문 "아무것도 누르지 않으면 그대로 둡니다"
5. **터미널 로그** — 1.5초 폴링, `after`로 새 줄만. 바닥을 보고 있을 때만 자동 스크롤. `cmd` 파랑 / `warn` 노랑 / `error` 빨강
6. **Dockerfile** — 접힌 상태. 출처와 포트 표시
7. **문제 이력** (지난 실패가 있을 때) — 접힌 상태. 단계·시각·해설 한 줄씩, 최신순. `features/deploys/ui/IssueHistory.jsx`
8. **동작 버튼** (`running`일 때) — [다시 배포] [삭제]. `needs_input`일 때는 [삭제]만 둔다([다시 배포]·[멈춤]은 숨김 - 이어가는 길은 카드의 [이어서 배포] 하나뿐).

**계획 E 에서 더한 것**: 맨 윗줄에 `← 목록` 링크와 오른쪽 `설정` 링크(`deleting`·`deleted`가 아니면 보임, `/deploys/{d_id}/settings`)가 있다. `open_incident_id`가 있으면 머리 카드 다음에 **인시던트 카드**("문제가 있습니다" + 상태 배지 + 한 줄 요약 + `자세히 보기 ›`, 카드 전체가 `/incidents/{id}` 링크, `features/incidents/ui/IncidentCard.jsx`)가 뜬다. 요약을 못 받아도 카드는 남는다. 주소 카드의 헬스 배지 글은 `HEALTH_STATE_LABEL`(`응답 정상`·`응답 없음`·`확인 전`).

**폴링**: 진행 중이거나 로그가 더 올 때는 1.5초, `running`이면 15초마다 계속 다시 읽는다(새로 생기는 인시던트 카드를 알아채도록). 읽기가 실패해도 `running`이면 15초 뒤 다시 시도한다. 그 밖의 상태에서는 멈춘다.

멈춤 확인 대화상자는 `features/deploys/ui/StopDialog.jsx`로 뺐다 (상세와 인시던트 상세가 같은 것을 쓴다).

`needs_input`이면 머리 카드 위(번호 목록 맨 위)에 파란 안내 한 줄 "환경변수 입력이 필요합니다. 아래에서 값을 입력하거나 건너뛴 뒤 [이어서 배포]를 누르세요."가 뜨고, 환경변수 카드는 머리 카드(단계 진행 막대가 들어 있다) 바로 밑에 붙는다.

**삭제 확인 대화상자** — "ECS 서비스와 ECR 이미지가 함께 지워집니다. 되돌릴 수 없습니다." [그대로 두기] [삭제]. 기본 포커스는 안전한 쪽.

### 묻는 방식 (기획서 03장)

열린 질문("어떻게 할까요?")이 아니라 **버튼 두세 개**. 파괴적인 동작은 빨간 테두리 + 확인 대화상자. 설정 변경이 곧바로 배포로 이어지지 않는다.

### 환경변수 카드 (S-19) — `features/envvars/ui/EnvVarsCard.jsx`

배포 상세에서 `showsEnvCard(status)`인 상태(`deploys/ui/constants.js`)일 때, 머리 카드(단계 진행 막대 포함) 바로 밑에 나온다. 스스로 `GET /api/deploys/{d_id}/env`를 읽고, 배포 `status`가 바뀔 때마다 다시 읽는다(`needs_input`부터는 페이지 폴링이 멈추기 때문). 읽은 행이 없고 `needs_input`이 아니면 카드 자체를 그리지 않는다. 버튼을 누르는 동안(`busy`)은 모든 버튼·입력이 잠긴다.

- 머리말: "코드에서 필요한 값을 찾았습니다. 값은 이 화면에서만 입력하고, 한 번 저장하면 다시 보여 드리지 않습니다." 행이 하나도 없는데 `needs_input`이면 "입력할 환경변수를 찾지 못했습니다. [이어서 배포]를 눌러 계속하세요."
- **묶음** (`groupEnvVars`, 행을 버리지 않는다): ① "꼭 필요해 보이는 것"(필수, 값 없음, 종류 확정) ② "종류를 모르는 것"(필수, `kind: unknown`) ③ "기본값이 있어 비워도 되는 것"(필수 아님, 접을 수 있지만 처음부터 펼침) ④ "입력 완료"(`set`·`skipped`, 접을 수 있지만 처음부터 펼침). 제목 옆에 개수. 빈 묶음은 그리지 않는다.
- **행**: 변수 이름(고정폭), 종류 배지, `source_hint`(`파일:줄`), 완료면 `입력됨`/`건너뜀` 배지.
  - `config` 종류: 값 입력창 + [저장] + [건너뛰기]. 입력창은 `autoComplete=off`, 최대 2000자. 저장에 **성공했을 때만** 입력창을 비우고, 실패하면 값을 그대로 둬서 다시 시도할 수 있다.
  - `unknown` 종류: "이 변수는 어떤 종류인가요?" + 종류 버튼 다섯 개(`ENV_KINDS`: 데이터베이스 주소 / 캐시 주소 / 외부 서비스 키 / 비밀값 / 일반 설정) → `PUT {kind}`. [건너뛰기]도 함께 나온다(`PUT {skip:true}`, 서버가 `unknown` 종류의 건너뛰기를 받는다) — 이것이 "잘 모르겠음" 길이다. 다섯 종류에 없는 `kind` 문자열도 `unknown`으로 다뤄 값 입력창을 주지 않는다. 필수가 아닌 `unknown` 행에도 같은 버튼이 나온다(서버가 `unknown` 종류에는 값을 받지 않아서 이것이 유일한 길).
  - **시크릿 종류 규칙**(`database` `cache` `external_api` `secret`): 값 입력창을 **절대 주지 않는다**. "이 종류의 값은 아직 저장할 수 없습니다. 지금은 건너뛰기만 됩니다." + [건너뛰기]만. 서버가 PUT에 501을 답하는 상태(결정 D8: 사용자 AWS 보안 저장소 검증 전)와 맞춘 것이라, 501 응답을 화면에서 만날 일은 없다.
  - 완료 행: `입력됨`이면 [값 지우기](`DELETE .../value`), `건너뜀`이면 [건너뛰기 취소](`PUT {skip:false}`) — 잘못 건너뛴 것을 되돌릴 길이다.
- **직접 추가**: 이름 입력창 + 종류 선택(기본 "일반 설정") + [변수 직접 추가]. 이름은 서버와 같은 규칙(`^[A-Za-z_][A-Za-z0-9_]{0,99}$`)을 먼저 확인하고, 어긋나면 요청 없이 "이름은 영문자나 _로 시작하고, 영문자·숫자·_만 100자까지 쓸 수 있습니다."를 띄운다. 이미 목록에 있는 이름이면 요청 없이 "이미 목록에 있는 변수입니다"를 띄운다(기존 변수의 종류·값이 바뀌지 않게). 오류 문구는 입력창과 `aria-describedby`로 이어진다. 그 밑에 "자동으로 찾지 못한 변수가 있을 수 있습니다. 배포 후 앱이 시작하지 못하면 알려 드립니다."
- **다시 배포 안내**: `PUT` 응답이 `needs_redeploy: true`이면 카드 안에 주황 알림 "다시 배포해야 적용됩니다" + [다시 배포](`POST /redeploy`와 같은 동작). 누르면 알림이 사라진다. 파이프라인이 진행 중(`isProgress`)이면 문구만 보이고 버튼은 없다(재배포가 409). 눌러야만 재배포한다(자동 아님, 규칙 3).
- **[이어서 배포]** (카드 맨 밑, `needs_input`일 때만): 값이 비어 있는 필수 변수(`required`이고 `status: detected`)가 있으면 비활성 + 옆에 "필수 환경변수에 값이 없습니다". 없으면 활성 → `POST /env/continue`. 서버가 409로 거절하면 이유(`detail`)를 카드 안 빨간 알림으로 보이고 입력은 그대로 둔다. 성공하면 상세 페이지가 다시 읽어(`status: queued`) 폴링을 재개한다. `queued`는 `showsEnvCard` 상태가 아니라서 카드 전체가 사라진다.
- 값은 쓰기 전용(규칙 6): 응답에는 `has_value`만 있다. 저장된 값은 화면에 남기지 않는다 (저장에 성공하면 입력칸을 비운다). 입력 중인 값은 저장에 성공하기 전까지(실패한 뒤에도) 그 행의 입력칸 상태에만 있고, `localStorage`·URL·콘솔·오류 문구에는 남기지 않는다.
- 접근성: 변경 뒤 눌렀던 버튼이 사라져 포커스를 잃으면 카드 제목(`h2`)으로 옮긴다.

### 분석 결과 패널 (S-20) — `features/advice/ui/AdvicePanel.jsx`

새 배포 폼(`DeployForm.jsx`)은 **두 단계**다: 주소(와 브랜치) 입력 → [분석] → 결과 패널 → [이 레포로 배포]. 폼의 제출 버튼은 [분석]뿐이라 분석 없이 바로 배포하는 길은 없다. [분석]은 `POST /api/deploys/advice`(읽기 전용 - 배포 기록도 AWS 호출도 없음)를 부르고 "분석 중..."으로 바뀐다. 중복 클릭은 막는다.

패널(폼 카드 밑, 결과가 나오면 제목 "분석 결과"로 포커스 이동):
- 언어(고정폭) + `공식 지원`(초록)/`실험 지원`(주황) 배지 + `앱 폴더: {app_dir}`(`app_dir`이 비어 있지 않고 `.`이 아닐 때만).
- `추천 수준: 가벼움/보통/무거움`(`small/medium/large`) + 배지 `확신도 낮음/보통/높음`. 낮음은 주황 배지 + "추정입니다. 근거가 부족해 틀릴 수 있습니다.", 높음은 초록 배지.
- "왜 이렇게 추천했나" — `reasons` 목록.
- 비용 줄: 최소·최대가 **둘 다** 숫자일 때만 `예상 비용: {min}~{max} {통화}/월`(+기준일·메모). 하나라도 `null`이면(지금은 항상 그렇다) "예상 비용: 아직 계산할 수 없습니다 (실제 배포로 요금 구성을 확인한 뒤 표시됩니다). 트래픽에 따라 늘어납니다." 비용 숫자가 없으면(null) "아직 계산할 수 없습니다"를 보여 준다. `cpu`·`memory`는 아예 그리지 않는다.
- "필요한 것" — 만들어 줄 수 있는 것은 그대로, 못 만드는 것(`supported: false`)은 흐리게 + ` — {message}`(예: `데이터베이스 — 마법사가 아직 만들어 주지 못합니다`). `env_vars`는 개수가 있으면 "환경변수 {n}개 입력이 필요합니다".
- "알 수 없었던 것 (n)" — 접을 수 있지만 처음부터 펼쳐 둔다.
- 비어 있는 `reasons`·`needs`·`unknowns`는 제목째로 생략한다.
- 버튼: [이 레포로 배포](주 버튼, `POST /api/deploys` → `/deploys/{d_id}`로 이동) · [다른 레포로](패널을 지우고 폼으로 돌아간다). 아래 안내: "분석은 읽기만 합니다. 배포를 누르기 전에는 AWS에 아무것도 만들지 않습니다."
- **패널이 낡지 않게**: 주소·브랜치·연결 블록(AWS 계정, GitHub 설치)이 바뀌거나 [브랜치 고르기]가 끝나면 패널을 지우고, 아직 오지 않은 이전 응답은 버린다.
- 분석이 실패(예: 400 주소 형식)하면 패널 없이 폼 카드 안 빨간 알림에 서버 `detail`. 패널이 떠 있는 채 배포 생성이 실패하면 오류는 패널 아래에 보인다.

### 수준 선택 3칸은 아직 없다

S-20 와이어프레임의 "수준 선택 3칸"(사용자가 가벼움/보통/무거움을 고르는 UI)은 **만들지 않았다**. 고른 수준을 저장할 `size_tier` 열과 배포 API가 아직 없고, 수준마다의 CPU·메모리 조합과 요금은 실제 배포로 검증하기 전(결정 D10)이라 고르게 해도 반영할 곳이 없기 때문이다. 지금 패널의 "추천 수준"은 보여 주기만 한다. 백엔드가 생기면 그때 패널에 얹는다.

### 반응형 (좁은 화면)

모든 화면(목록·새 배포 폼·상세·계정 연결·안내 창·대화상자)이 휴대폰 너비까지 맞다. 규칙은 전부 `shared/ui/styles.css`에 있고(색은 기존 토큰만), 상세 화면의 `← 목록` 링크만 `back-link` 클래스를 달았다. 데스크톱(1280px)·태블릿(768px) 모양은 의도적으로 바꾸지 않았고 눈에 띄는 변화는 확인하지 못했다(긴 단어가 넘칠 때만 줄바꿈하는 기본 규칙은 모든 너비에 걸려 있다). 예외 둘: 계정 상자 아래 버튼 줄은 900px 이하부터 줄을 바꾸고, 연결 안내 창은 데스크톱에서도 `width=480` 팝업(`guideWindow.js`)으로 열려 640px 이하 폰 규칙을 그대로 받는다.

- **기준 너비**: 휴대폰은 `max-width: 640px` 미디어 쿼리. 그보다 넓으면 기존 모양.
- **글이 잘리지 않는다**(2026-11-15 규칙, `docs/conventions.md`): `line-clamp`·`text-overflow: ellipsis`·`font-size: 0`·`overflow: hidden` 으로 내용을 가리지 않는다. 터미널·`pre`(Dockerfile)만 자기 칸 안에서 스크롤한다. 긴 글은 줄바꿈하고, 배지도 길면 줄바꿈한다(`max-width: 100%`). 처음부터 접어 두는 것은 길고 한 번 눌러 펼치는 Dockerfile 과 문제 이력뿐이다. 640px 이하에서도 상단 바의 안내 문구(`.topbar-note`)는 숨기지 않고 한 줄을 따로 쓰며, 단계 진행의 칸 이름은 줄바꿈해 4칸씩 두 줄로 보인다(11px).
- **가로 스크롤 없음**: 긴 레포 이름·주소·ARN·오류 문장·변수 이름은 `overflow-wrap: anywhere`로 줄바꿈한다. 코드·로그 블록(`pre`, 터미널)만 자기 칸 안에서 스크롤하거나 줄바꿈한다.
- **터치 크기**: 640px 이하에서 버튼·입력·선택 상자·링크(상단 바, `← 목록`, 안내 단계 안 링크는 `.guide-step a`의 위아래 패딩 10px)·`<summary>`·계정 화살표(`button.account-arrow`)는 높이 40px 이상(글자 크기는 안 바꾸고 패딩으로 맞춘다).
- **여백**: `.page` 좌우 16px(상단 바와 같아 로고와 카드의 왼쪽 선이 맞는다), `.card` 안쪽 16px. 상단 바는 줄바꿈 가능, 새 배포 폼의 한 줄 입력(주소 선택·브랜치·분석 버튼)은 `form.card > .row > *` 규칙으로 세로로 전체 너비이며, 같은 규칙이 `AccountPicker`의 선택 상자도 전체 너비로 만든다.
- **목록**: 상태 배지는 줄어들지 않고 오른쪽 위에 붙는다. 긴 이름은 줄바꿈.
- **상세**: 해설 카드 버튼은 세로 전체 너비, 터미널 높이는 `min(360px, 60vh)`.
- **대화상자**: 최대 너비 `min(440px, 100% - 32px)`. 넓은 대화상자 `dialog.wide`는 `width: calc(100% - 32px)`에 `max-width: 720px`. 내용이 최대 너비를 채우는 폰 폭에서는 양옆 16px 여백이 남는다. 640px 이하에서 안쪽 패딩 16px, `dialog input.grow`(블록 추가 창의 입력)만 전체 너비.
- **계정 연결**: 상자 아래 버튼 줄(`.account-foot`)은 상자 두 개가 나란히 좁아지는 900px 이하부터, 자리가 모자라면 줄을 바꾼다(2+1). 안내 그림의 입력 칸(`.shot-input`)은 [복사] 버튼과 높이를 맞춘다.
- **다크 모드**: 같은 토큰을 쓰므로 따로 규칙이 없다.

확인한 것 (2026-11-09, Playwright + 모의 `/api`, 실제 백엔드·실제 기기는 아님): 목록·상세(실패·입력 필요 등 상태별)·계정 연결을 390px 라이트·다크와 768·1280px 라이트에서, 계정·안내 페이지는 360·320px에서도 한 번씩 가로 스크롤 없음과, 390px에서 측정한 조작 요소(링크·버튼·입력·선택 상자·`<summary>`)에 40px 미만이 없음을 쟀다. 알려진 예외: 상세 화면의 `.endpoint` 링크는 주소가 한 줄에 들어가면 높이가 약 27px이다(모의 데이터의 62자 주소는 줄이 바뀌어 측정에 안 걸렸다). 이후 보정(2026-11-09): 768·700px에서 상자 아래 버튼이 한 줄 라벨로 나오고 390·360·320px에서 가로 스크롤이 없음, 안내 단계 안 링크 41px, 목록 로고와 카드의 왼쪽 선이 16px로 같음을 쟀다. 최종 점검은 390×844 다크와 1280×900 라이트에서 목록 → 실패 상세 → 입력 필요 상세 → 계정 연결을 돌려 `scrollWidth ≤ innerWidth`와 콘솔 오류(모의하지 않은 엔드포인트 404만)를 확인했다.

**확인 못 한 것**: 실제 휴대폰, 320px 미만, 가로로 눕힌 화면(보통의 폰 가로 667~932px는 640px 쿼리에 안 걸려 데스크톱 배치를 받는다. 이 모양은 확인하지 않았다. 터미널 높이 `vh`는 폭 640px 이하에서만 쓰인다), 단계 막대 라벨의 375px 미만 모습, 320px에서 안내 그림(`.shot`) 안쪽 요소가 잘리는지(`scrollWidth` 검사로는 증명할 수 없다). 자동 시각 회귀 테스트는 없다.

## 3. 계정 연결 (`/accounts`, M6)

상단 네비게이션 "계정 연결" 링크로 이동. 카드 두 개.

**AWS 계정** — 연결 목록(라벨, 계정 번호, 상태 배지 `pending`/`verified`/`invalid`) + `[새 AWS 계정 연결]`.
- 새 연결은 대화상자 2단계: ① 라벨 입력 → `POST /aws` ② 발급된 `external_id`·우리 계정 번호를 보여주고, 단계별 안내(`AwsStackGuide.jsx`, 넓은 대화상자 `dialog.wide`) — 템플릿 다운로드, 콘솔 스택 생성 화면 바로가기(`stack_create_url`, 새 탭), 단계마다 콘솔 화면을 단순하게 그린 그림(`.shot`, 실제 스크린샷 아님), 스택 이름·`TrustedAwsAccountId`·`ExternalId`는 값마다 [복사] 버튼, IAM 승인 체크, [출력] 탭 위치 → 역할 ARN 붙여넣기. 실패 메시지는 대화상자 안에도 표시. 창을 닫은 `pending` 연결은 목록의 [역할 ARN 입력]으로 이어서 한다(ExternalId는 다시 안 보여줌). `verified` 연결 줄에는 템플릿 상태 한 줄("템플릿 최신 (버전 N) · S3에 올린 템플릿 파일 N개 남음 / 남은 템플릿 파일 없음")을 보여주고, 남은 파일이 있을 때만(`template_file_count > 0`) [템플릿 파일 삭제]를 띄운다 — 지우면 상태를 다시 읽어 버튼이 사라지고 문구가 바뀐다. 확인 대화상자 후 `DELETE /aws/{a_id}/template-files`, 결과는 초록 알림(`.notice.ok`). 목록을 불러올 때 `verified` 연결마다 `GET /aws/{a_id}/template-status`를 물어보고, `update_needed`면 그 줄에 주황 안내(`.notice.warn` "스택 업데이트 필요")와 [스택 업데이트] 버튼을 띄우고 [템플릿 파일 삭제]는 숨긴다. 버튼은 업데이트 안내 대화상자(`AwsStackUpdateGuide.jsx`, 5단계 그림) → [업데이트 확인]이 상태를 다시 읽어 최신이면 닫고 초록 알림, 아니면 창 안에 "아직 예전 버전" 표시
- **화면은 연결 블록 단위다** (2026-10-06, 배치는 2026-10-08에 바꿈). 맨 위 제목 "계정 연결". 그 아래 블록 카드를 **한 번에 하나만** 보여준다 = 이름 + 오른쪽 [＋ 블록 추가](이름만 물어 빈 블록을 만든다)·[블록 삭제] + 상자 두 개(`AccountBox.jsx`, `.account-boxes` — 왼쪽 AWS 계정, 오른쪽 GitHub 계정, 좁은 화면에서는 위아래). 블록이 하나도 없을 때만 [＋ 블록 추가]가 제목 오른쪽에 뜬다. 새 배포 폼의 `AccountPicker`는 블록 하나를 고르는 드롭다운 하나다.
  - 블록 카드 맨 밑(`.block-pick`): 양 끝의 `‹` `›`로 블록을 넘기고, 가운데 `n / 전체`와 그 밑 [선택]으로 새 배포에 쓸 블록을 고른다(고른 블록은 "선택됨"). 고른 블록은 이 브라우저의 `localStorage`(`dw-picked-block`, `pickedBlock.js`)에만 기억하고, `AccountPicker`가 블록이 여럿일 때 그것을 미리 골라 둔다. 블록이 하나뿐이면 늘 "선택됨"이다.
  - 상자 하나: 위 왼쪽 이름("AWS 계정"/"GitHub 계정"), 위 오른쪽 상태 배지(이 블록이 쓰는 계정을 보는 중이면 그 상태, 아니면 "연결 안 됨"). 가운데 `‹ 계정 정보 ›` — 화살표로 이미 연결해 둔 계정(AWS는 `GET /aws`, GitHub는 `GET /github` 전부)을 넘겨 보고, 그 아래 `n / 전체`, 다시 그 밑에 [선택](이 블록에 잇는다 → `PATCH /connections/{c_id}`. 이미 쓰는 계정이면 "선택됨"으로 잠긴다). 아래 줄(`.account-foot`)은 왼쪽 [계정 추가], 가운데 [연결 확인], 오른쪽 [연결 해제].
  - [계정 추가]: 블록에 아직 계정이 없으면 새로 연결해 이 블록에 잇는다(AWS는 블록 이름으로 `POST /connections/{c_id}/aws`, GitHub는 설치 주소에 `c_id`). 이미 있으면 새 계정만 만들고 블록은 그대로 둔다 — AWS는 이름을 묻는 창 → `POST /aws` → 안내 창, GitHub는 `c_id` 없이 설치 화면. 연결을 마친 뒤 화살표로 찾아 [선택]한다.
  - 가운데 버튼은 보이는 계정의 상태에 따라 바뀐다: AWS가 `pending`이면 [역할 ARN 입력], `invalid`면 [다시 확인], 그 밖에는 [연결 확인]. [스택 업데이트]·[템플릿 파일 삭제]는 상자 가운데 계정 정보 밑에 뜬다.
  - [연결 해제]는 이 블록이 쓰는 계정을 보고 있을 때 눌린다(AWS는 어느 블록도 안 쓰는 계정을 보고 있을 때도 — 확인 뒤 연결을 지운다). GitHub는 블록에서 떼기만 한다. AWS는 다른 블록도 그 계정을 쓰면 이 블록에서만 떼고, 이 블록만 쓰면 확인 대화상자 뒤 연결을 지운다(`DELETE /aws/{a_id}`).
- **연결은 "안내 창 + 작업 창"으로 한다** (`/guide/github`, `/guide/aws` — `ConnectGuidePage.jsx`, 상단 바 없는 좁은 팝업, `guideWindow.js`의 `openGuideWindow`). 팝업은 반드시 클릭 처리 안에서 바로 연다(서버 응답을 기다린 뒤 열면 차단된다).
  - GitHub: [GitHub 연결] → 안내 창이 뜨고 원래 창은 GitHub 설치 화면으로 이동 → 설치가 끝나면 GitHub가 원래 창을 `/accounts?connected=github`로 돌려보낸다 → 원래 창이 주소를 정리하고 `BroadcastChannel('dw-accounts')`로 `github-connected`를 보내 안내 창을 닫게 하고, `GET /github/{g_id}/check` 결과를 초록 알림으로 보여준다.
  - AWS: [새 AWS 계정 연결] → 이름 → [다음] → 안내 창이 뜨고(값은 `postMessage`로 전달, ExternalId를 주소에 싣지 않는다) 원래 창의 대화상자는 닫힌다 → 안내 창 7번에서 RoleArn을 넣고 [확인] → 안내 창이 `aws-connected`를 알리고 닫히며 원래 창이 앞으로 온다 → 원래 창이 목록을 새로 읽고 확인 결과를 알린다. 팝업이 차단되면 예전처럼 원래 창 안의 대화상자로 안내한다.
  - 연결된 줄마다 [연결 확인] — AWS는 역할을 다시 빌려 보고(`reverify`), GitHub는 설치 토큰으로 레포를 세어 본다.
- 배포 상세(`/deploys/:d_id`): `running`이면 [다시 배포] [멈춤] [삭제], `stopped`이면 안내 카드의 [다시 켜기] + [삭제]. 멈춤·삭제는 확인 대화상자, 다시 켜기는 버튼 한 번 → `PATCH /aws/{a_id}/role-arn`.
- `invalid` 행에는 `[다시 확인]`(`POST /aws/{a_id}/reverify`)과 실패 사유(`last_error`)를 보여준다.

**GitHub 연결** — 연결 목록(계정 이름, 개인/조직, 전체/선택 레포, 상태 배지) + `[GitHub 연결]`(누르면 바로 GitHub 설치 화면으로 이동, 대화상자 없음).
- 설치를 끝내면 GitHub이 콜백으로 돌려보내고(`?connected=github`), 목록에 바로 나타난다.

두 카드 모두 삭제는 확인 대화상자 — "이 연결을 쓰던 배포들의 연결이 끊깁니다. 앱 설치나 CFN 스택 자체는 지워지지 않습니다" 안내(연결만 끊는다는 뜻, 실제 회수는 각자 콘솔/github.com에서 하라는 것을 명확히).

## 4. 운영 화면 (계획 E)

웹에서 인시던트·알림·배포 설정을 본다. 서버가 하는 재시작·되돌리기는 **읽기 전용 기록**으로만 보여 주고, 웹은 자동 조치를 하지 않는다 (CLAUDE.md 규칙 3). 상태를 바꾸는 것은 전부 사용자가 누른 버튼이다. API 와 상태 값은 바뀐 것이 없다 (`docs/api-spec.md`).

- 서버 필드 이름(`i_id`, `d_id`, `open_incident_id`, `open_incident_status`, `health_state`, `auto_recover`, `explain.fix_where` ...)과 상태·종류 값은 백엔드와 같고 각 기능의 `ui/constants.js`에 한 번만 적는다 (`features/incidents/ui/constants.js`, `features/notifications/ui/constants.js`, `features/deploys/ui/constants.js`의 `HEALTH_STATE_LABEL`). 모르는 값은 서버 글자 그대로 보여 주고 화면이 죽지 않는다.
- 서버 시각은 UTC 이고 `Z`가 없다. 모든 시각은 `shared/ui/time.js`의 `toMs`/`formatTime`/`durationText`로 읽는다.
- `explain`·`summary`·조치 `detail`은 글자로만 그린다 (React 이스케이프, `dangerouslySetInnerHTML` 없음). `evidence`는 받아도 화면에 그리지 않는다. 토큰은 주소·`localStorage`·콘솔에 두지 않는다 (규칙 6).

### 인시던트 상세 (`/incidents/:i_id`, S-13) — `features/incidents/ui/IncidentDetailPage.jsx`

위에서부터:

1. **머리 카드** — 한 줄 요약(`summary` → `explain.summary` → "문제가 감지되었습니다") + 상태 배지(감지됨 · 복구 중 · 해결됨 · 확인 필요), `배포 #d_id · 종류 · 감지 시각`(해결되면 ` · 해결 시각 (걸린 시간)`), 처리 중(`open`·`recovering`)이면 "마법사가 복구를 시도하고 있습니다. 이 화면은 5초마다 새로 고쳐집니다.", [새로 고침].
2. **원인 · 고칠 곳 · 해야 할 일** (`IncidentExplain.jsx`) — `explain`이 `null`이거나 일부만 있어도 그린다 (원인이 없으면 "아직 원인을 확인하지 못했습니다"). 고칠 곳은 고정폭 `pre`라서 선택·복사되고 긴 ARN 도 줄바꿈하며 [복사] 버튼이 있다 (클립보드를 못 쓰면 "고칠 곳을 복사하지 못했습니다"). 해야 할 일은 번호 목록.
3. **마법사가 한 일** (`IncidentTimeline.jsx`, 순서는 `incidentTimeline`) — 세로 타임라인: 문제를 감지했습니다 → 조치마다 `{재시작 | 이전 버전으로 되돌리기} 시도`와 `... 성공 | 실패`(+서버가 마스킹한 `detail`) → `정상으로 돌아왔습니다` 또는 `확인이 필요합니다`. 읽기 전용 기록이다.
4. **헬스체크 이력** (`HealthBar.jsx`, 칸 계산은 `health.js`의 `healthBuckets`) — 최근 24시간을 15분 칸 막대로(정상 / 실패 / 기록 없음) 그리고 요약 `최근 24시간 정상 N%`를 읽어 준다. 이력을 한 번도 못 받았으면 "헬스 이력을 불러오지 못했습니다"(인시던트는 그대로 보인다), 받는 중에는 막대를 그리지 않는다.
5. **버튼** — `needs_action`일 때만 [다시 배포] [멈춤] [그대로 두기]와 "아무것도 누르지 않으면 그대로 둡니다. 마법사가 자동으로 지우거나 바꾸지 않습니다." [멈춤]은 `StopDialog`(기본 포커스 [그대로 두기]) 뒤에서만 실행된다. 동작이 성공하면 안내 + 새로 받고, 버튼 대신 [배포 보기]만 남는다. 실패하면 빨간 알림을 맨 위로 올려 보인다. 다른 상태에서는 [배포 보기]만 있다. 삭제 버튼은 없다.
- 없는 인시던트(404)·지워진 배포: "문제를 찾을 수 없습니다. 이미 삭제된 배포이거나 지워진 기록일 수 있습니다." + [돌아가기](바로 연 화면이면 목록, 아니면 뒤로). 첫 불러오기 실패는 오류 + [다시 시도] [돌아가기].
- **갱신**: `open`·`recovering`인 동안 5초마다, `resolved`·`needs_action`이 되면 멈춘다. 실패하면 5 → 10 → 20 → 30초로 늘려 다시 시도하고 404 는 다시 부르지 않는다. 끝난 상태(`resolved`·`needs_action`)를 받아 둔 뒤의 실패도 다시 부르지 않는다([새로 고침]만). 주소의 `i_id` 가 양의 정수(2147483647 이하)가 아니면 요청 없이 "문제를 찾을 수 없습니다" 를 보인다. 숨겨진 탭에서는 멈췄다가 보이면 한 번 바로 부른다. 헬스 이력은 인시던트 갱신과 따로 받는다: 첫 응답, 상태가 바뀔 때, [새로 고침], 60초가 지났을 때만. 이력 요청이 실패해도 지난 이력은 그대로 둔다. 주소의 `i_id`가 바뀌면 화면을 새로 만든다.

### 배포 설정 (`/deploys/:d_id/settings`, S-14) — `features/deploys/ui/DeploySettingsPage.jsx`

- 머리 `{레포} · 배포 #d_id`, 맨 위 `← 배포로`. 스위치 둘(`shared/ui/SettingSwitch.jsx`, 줄 전체가 하나의 스위치): `새 커밋이 오면 자동 재배포`(`auto_redeploy`), `문제가 생기면 자동 복구`(`auto_recover`). 자동 복구 설명에 "자동 복구는 재시작과 이전 버전으로 되돌리기만 합니다. 삭제나 사양 변경은 직접 확인한 뒤에만 합니다."가 들어 있다. 값이 없는 옛 응답은 서버 기본값(자동 복구 켜짐, 자동 재배포 꺼짐)으로 본다.
- 누르면 저장 버튼 없이 바로 `PATCH /api/deploys/{d_id}/settings`(바꾼 항목 하나만). 먼저 새 값으로 보이고 같은 스위치는 응답이 올 때까지 잠근다(더블 클릭 방지, 끝나면 키보드 포커스를 되돌려 준다). 성공하면 "저장했습니다"(3초), 실패하면 그 스위치만 되돌리고 서버 문구를 빨간 알림(`role="alert"`)으로 보인다. 안내는 스위치 목록 **아래**에 띄워 더블 클릭 때 줄이 밀리지 않게 하고, 화면 밖이면 보이는 곳까지만 스크롤한다. 그 사이 배포가 지워져 404 가 오면 없는 배포 안내로 바꾼다. 폴링은 없다 (처음 한 번만 읽는다).
- 들어가는 길은 배포 상세 맨 윗줄의 `설정` 링크 하나다.

### 알림 목록 (`/notifications`, S-12) — `features/notifications/ui/NotificationsPage.jsx`

- 맨 위 `알림` 제목과 [알림 설정] 링크 · [새로 고침] · [모두 읽음].
- 줄(`NotificationItem.jsx`): 종류 아이콘(글자 모양 선택자를 붙여 색깔 이모지가 안 되게 한다), 제목, 본문 전체(줄바꿈 그대로, 길면 줄바꿈), 시각. 읽지 않은 것은 굵은 제목 + 점. 스크린 리더에는 화면에 안 보이는 글 `읽지 않음 · {종류}: ` 을 제목 앞에 붙여 읽어 주고(제목·본문·시각을 가리지 않는다), 종류나 제목이 없으면 그 부분만 뺀다.
- 줄을 누르면 먼저 읽음으로 보이고(요청은 뒤에서) 이동한다: `incident_*`는 `/incidents/{i_id}`, 그 밖은 `/deploys/{d_id}`. id 가 없거나 믿을 수 없으면(`d_id`가 `null`인 `new_commit` 등) 이동 없이 읽음만 한다. 600ms 안의 같은 줄 두 번째 누름과 요청 중인 줄은 무시한다. 읽음 요청이 실패하면 되돌리고 맨 위에 빨간 안내를 올린다.
- [모두 읽음] — 읽지 않던 줄만 먼저 읽음으로 보이고, 실패하면 그 줄들만 되돌린다. 읽을 것이 없으면 비활성.
- 한 쪽은 100건이다. 100건을 받았으면 [더 보기](가장 오래된 `n_id`를 `after`로 보내고, 이미 있는 `n_id`는 건너뛰므로 겹치는 응답도 중복되지 않는다). 비었으면 `새 알림이 없습니다`, 첫 불러오기 실패는 오류 + [다시 시도], 새로 고침이 실패하면 목록 위에 안내.
- **상단 바 `알림` 알약** (`BellLink.jsx`, `useUnreadCount.js`): 읽지 않은 수(99 를 넘으면 `99+`, 라벨 `알림, 읽지 않은 N개`). 30초마다 `GET /api/notifications/unread-count`를 읽고(실패하면 늘려 가며, 숨겨진 탭에서는 멈춤), 알림 화면에서 읽음 처리가 되면 창 이벤트 `dw:unread-changed`로 바로 다시 받는다. 실패하면 0 으로 보이고 안내는 없다. 실패가 이어지면 간격을 30초 → 60 → 120 → 240 → 300초(5분)까지 늘린다.

### 알림 설정 (`/notification-settings`, S-15 알림 부분) — `features/notifications/ui/NotificationSettingsPage.jsx`

- `받는 방법`: `메일 받기`(`notify_email`, "서버에 메일 설정이 있을 때만 보내집니다"), `푸시 받기`(`notify_push`). 푸시는 **서버 전체 설정**이고 안내문에 "푸시는 앱에서 이 기기를 등록해야 도착합니다. 웹 브라우저로는 받지 않습니다. 이 설정은 모든 기기에 적용됩니다."라고 적었다. 웹은 푸시 권한을 묻거나 기기를 등록하지 않는다 (S-17 은 앱 전용).
- `알림 종류` 여섯 개(문제 감지 · 복구 완료 · 확인 필요 · 배포 성공 · 배포 실패 · 새 커밋, 서버 순서), 줄마다 설명 한 줄. 종류 스위치는 눌린 줄이 아니라 지금 값에서 목록 전체를 서버 순서로 다시 만들어 `kinds`로 보내므로 한 묶음으로 잠근다.
- 맨 아래 "끈 종류는 알림 목록에도 남지 않습니다. 변경은 누르는 즉시 저장됩니다."
- 저장 방식은 배포 설정과 같다 (즉시 `PATCH`, 성공 "저장했습니다", 실패하면 이 요청이 바꾼 값만 되돌리고 서버 문구, 예: 422). 실패 안내가 떠 있으면 저장 안내가 덮어쓰지 않는다. 폴링은 없다. 바로 연 화면에서 [돌아가기]는 알림 목록으로 간다.

### 갱신(폴링) 규칙

| 화면 | 간격 | 멈추는 때 |
|---|---|---|
| 인시던트 상세 | 5초 (실패 시 5→10→20→30초) | `resolved`·`needs_action`, 404, 화면을 떠남 |
| 인시던트 헬스 이력 | 첫 응답·상태 변경·[새로 고침]·60초 경과 | 화면을 떠남 |
| 상단 바 읽지 않은 수 | 30초 (실패 시 늘려 감) + 읽음 처리 때 바로 | 숨겨진 탭 |
| 배포 상세 | 진행 중 1.5초, `running` 15초 (실패해도 `running`이면 15초 뒤 재시도) | `running`도 진행 중도 아닌 상태(예: `failed`, `stopped`), 화면을 떠남, 읽기가 404(배포가 지워짐)면 멈추고 "배포를 찾을 수 없습니다" 안내 |
| 목록 | 진행 중 3초, 없으면 15초 | 화면을 떠남 |
| 알림 목록·알림 설정·배포 설정 | 없음 (처음 한 번 + 누를 때) | — |

상단 바 읽지 않은 수는 화면에 상관없이(폴링이 없는 알림 목록·설정 화면에서도) 30초마다 읽는다. 상단 바는 모든 화면에 있기 때문이다.

**`usePolling`**(`shared/ui/usePolling.js`, 인시던트 상세와 읽지 않은 수만): 번호(`seq`)로 늦게 온 응답을 버리고 `clearTimeout`으로 정리하며, 숨겨진 탭에서는 멈췄다가 다시 보이면 한 번 바로 부른다. 실패하면 `shared/ui/polling.js`의 `backoffDelay`로 간격을 두 배씩 늘린다. 인시던트 상세는 5초 기준 최대 30초(404 와, 끝난 상태 뒤의 실패는 다시 부르지 않는다), 읽지 않은 수는 30초 기준 최대 5분(`maxMs = 300000`)이다.

**배포 목록·상세**는 기존 `setTimeout` 루프이고 `alive` 표시와 `clearTimeout`만 쓴다 (번호 없음, 숨겨진 탭 멈춤 없음, 실패 간격 늘림 없음). 간격은 고정이다: 목록 진행 중 3초·아니면 15초(읽기 실패 뒤 10초), 상세 진행 중 1.5초·`running` 15초(실패해도 `running`이면 15초 뒤).

### 앱과 다른 점

- **아래로 당겨 새로고침 대신 [새로 고침] 버튼** (인시던트 상세, 알림 목록).
- **푸시·기기 등록 없음.** 알림 설정의 푸시 스위치는 서버 전체 설정이고 웹은 기기를 등록하지 않는다는 안내가 붙는다. 앱의 권한 안내 카드·푸시 준비 상태 표시도 없다.
- 상단 바 `알림` 링크가 앱의 종 버튼이다 (앱은 머리줄, 웹은 상단 바 `알림` → `계정 연결` 순서). 뒤로 가기는 브라우저, 확인 창은 `<dialog>`.
- 터치 크기는 640px 이하에서 40px 이상(웹 기존 규칙), 앱은 44pt 이상. 640px 를 넘는 너비에는 40px 규칙이 없어 상단 바 링크 약 21px, `← 목록`류 약 19px 이다 (기존 화면과 같다).
- 읽지 않은 수는 30초 폴링이고, 앱처럼 푸시로 바로 알려 주지 않는다.

### 확인한 것 (2026-11-15)

**전부 모의(`page.route('**/api/**')`)로만 했다. 실제 백엔드·AWS·SMTP·기기는 쓰지 않았다.** `npm run dev`(Vite)를 띄우고 Playwright 로 390×844 다크·라이트, 1280×800 라이트에서 목록(문제 배너·헬스 점·알림 알약) → 인시던트 `open → recovering → resolved` → `needs_action`(고친 곳 300자 이상 무공백 ARN, 재시작·되돌리기 실패 두 건) → `explain: null`·조치 없음 → 404 → 헬스 이력 정상/없음/500 → 알림 목록(읽음 한 건, 모두 읽음 실패→성공, 100건 쪽 + 겹치는 `after` 쪽) → 알림 설정(PATCH 성공·422) → 배포 상세 `설정` → 배포 설정(PATCH 성공·500) → 목록으로 돌렸다.

- 가로 스크롤 없음(`scrollWidth ≤ innerWidth`)을 위 모든 화면에서 확인했고 `main` 안에 화면 오른쪽 밖으로 나간 요소도 없었다(이 요소별 검사는 390px 라이트에서만 했고, 다크는 요소별로 다시 재지 않았다). 390px 에서 측정한 조작 요소(링크·버튼·스위치 줄·`<summary>`)의 가장 작은 높이는 40px 이다. 1280px 에서는 40px 규칙이 없어 상단 바 링크 20.8px, 뒤로 링크 19px 로 나왔다(위 "앱과 다른 점").
- 폴링: 인시던트 7 은 `open → recovering → resolved`를 화면에서 모두 봤고 `resolved` 뒤 11~12초 동안 요청이 늘지 않았다. `needs_action`(8)과 404(99)도 처음 요청 이후 늘지 않았다. 개발 서버는 React StrictMode 라 마운트 때 첫 요청이 두 번 나간다(요청 수에 그만큼 더해져 있다). `running` 배포 상세는 15초 간격으로 계속 읽고(16초에 3, 31초에 4) 다른 화면으로 가면 멈췄다. 읽지 않은 수는 31초에 한 번 더 읽었다. 목록은 16초에 한 번.
- 콘솔 오류는 모의하지 않은 엔드포인트(`/api/accounts/*`)의 404, 의도한 404(인시던트 99)와 500(헬스 이력·설정·모두 읽음 실패 변형)뿐이었다.
- **상단 바 `계정 연결` 링크가 잘려 보인다는 의심**(Task 5 구현자 보고): 390·375·360·340·320px 에서 재 봤다. 글자는 잘리지도 줄이 바뀌지도 않고(링크 높이 40px, 글자 줄 하나, 문서 가로 스크롤 없음) 스크린샷으로도 확인했다. 링크 상자 오른쪽 끝(390px 에서 x=382)이 `nav`보다 8px 삐져나오는 것은 알림 링크를 더하기 전부터 있던 `.topbar-link { padding: 0 8px; margin-right: -8px }` 규칙 때문이고(알림 링크를 숨겨도 똑같다), 글자는 16px 여백 선(x=374)에 맞는다. 이 CSS 는 Task 5 가 건드리지 않았다. **Task 5 가 바꾼 것은 한 가지**: (수정 전 측정, 2026-11-15 이후는 아래 "글이 잘리지 않는다"에서 안내 문구를 보이게 하면서 상단 바를 `display: contents` 로 바꿨고, 360px 이상은 로고·알림·계정 연결 한 줄 + 안내 문구 한 줄(74px), 343px 이하는 로고와 알림 다음 줄에 계정 연결, 그다음 줄에 안내 문구(114px)이다) 알림 링크 때문에 줄이 길어져서 안 읽은 알림 알약이 있을 때 약 331px 미만(`99+`이면 약 343px 미만)에서 상단 바가 두 줄(높이 53 → 93px)로 바뀐다. 잘리는 것은 아니고 360px 이상에서는 한 줄이다.

**확인 못 한 것**: 실제 백엔드(응답 모양은 `docs/api-spec.md` 기준으로 만든 모의), 실제 휴대폰·태블릿, 가로로 눕힌 화면, 750~1279px 중간 너비, 키보드·스크린 리더로 직접 돌려 본 것(접근성 속성만 코드로 확인), 자동 시각 회귀 테스트. 순수 로직(`time`·`health`·`timeline`·알림 로직·`backoffDelay`·`api.js`)은 `npm run test:web`(Node 22 `node:test`, 42개)로 돈다. 화면 컴포넌트 자체의 자동 테스트는 없다.

**알려진 빈틈** (고치지 않고 남김): 알림 설정·배포 설정의 안내가 바뀔 때마다 `scrollIntoView`가 불리고, 안내(`role="status"`)가 채워진 채로 나타나서 일부 스크린 리더가 읽지 않을 수 있다.

웹과 다르게 한 것:
- **계정 연결 화면 (C2)**: 맨 위 `계정 연결` 제목과 `＋ 블록 추가` 아래에 블록 카드가 **세로로 쌓인다** (웹의 한 번에 한 블록 + `‹ ›` 넘김은 없다). 카드마다 이름, `선택`(새 배포에 쓸 블록), `블록 삭제`, 그 안에 AWS 상자와 GitHub 상자. 고른 블록은 `AsyncStorage` 에 번호만 저장하고, 블록이 하나뿐이면 늘 `선택됨`이다. 목록은 아래로 당겨 새로고침, 목록 화면 상단 `계정 연결` 버튼으로 들어오고, 이 화면에서 돌아오면 목록을 다시 읽는다.
- **계정 고르기**: 웹의 상자 안 `‹ ›` 화살표와 `n / 전체` 대신 `이미 연결한 계정에서 고르기` 버튼이 목록(이 블록이 아직 쓰지 않는 계정만)을 띄우고, 하나를 누르면 `PATCH /connections/{c_id}`. 목록 창에 `닫기`가 있다.
- **상자 버튼**: 웹의 가운데·아래 줄 버튼 배치 대신 세로로 쌓은 버튼. 계정이 있을 때만 `연결 확인`(AWS `pending` 이면 `역할 ARN 입력`, `invalid` 면 `다시 확인`)과 `연결 해제`가 나온다. 접근성 라벨은 `<블록 이름> AWS 계정 추가`처럼 블록 이름을 앞에 붙인다.
- **AWS 안내**: 웹의 안내 팝업 창(`/guide/aws`) 대신 RN `Modal`(7단계 그림, 복사 버튼, 맨 위 오른쪽 `닫기`). 링크 줄은 `새 탭` 링크가 아니라 `템플릿 받기`·`콘솔 열기` 버튼이다. 원문의 "화살표로 찾아 [선택]"은 "[이미 연결한 계정에서 고르기]"로 바꿨다. 상자에는 역할 ARN 전체를 고정폭으로 보여 준다 (웹은 역할 이름만).
- **GitHub·AWS 에서 돌아오기**: 딥링크가 없다 (서버의 콜백 페이지와 `BroadcastChannel` 은 앱에서 쓰지 않는다). `계정 추가` 가 설치 주소를 열고 "설치를 마치고 이 앱으로 돌아오세요." 안내를 보여 주며, 앱이 다시 앞으로 올 때(`AppState`, 한 번 돌아올 때 한 번) 목록을 다시 읽는다. 이 블록에 아직 GitHub 연결이 없었고 설치가 이어졌으면 `연결 확인` 을 한 번 부른다. 돌아왔는데도 설치가 없으면 "아직 설치가 확인되지 않았습니다. GitHub 설치를 마쳤는지 확인하고 다시 시도하세요. 서버의 GitHub 앱 콜백 주소를 이 폰에서 열 수 없으면 PC에서 연결해야 합니다." 를 복귀마다 한 번 보인다 (앱 전용). **GitHub 앱에 등록된 콜백 주소가 폰의 브라우저에서 열려야 한다.** 열리지 않으면 서버가 설치를 저장하지 못해 앱으로 돌아와도 아무것도 바뀌지 않는다. 이미 연결이 있는 블록에 새 계정을 더하면 서버가 블록에 잇지 않으므로(웹도 같다) 안내에 `이미 연결한 계정에서 고르기` 를 덧붙인다.
- **바깥 링크는 https 만**: 콘솔·GitHub 설치 주소는 `https://` 로 시작할 때만 연다 (아니면 `주소를 열 수 없습니다`). 템플릿 내려받기는 서버가 준 상대 경로를 API 주소에 붙이는데, 폰에서는 API 주소가 LAN 주소일 때만 열린다.
- **ExternalId**: `계정 추가` 응답의 값은 안내 창이 열려 있는 동안만 화면 상태에 둔다 (주소·경로 인자·저장소·로그·오류 문장·접근성 라벨 없음). 복사 버튼의 접근성 이름은 `<계정 이름> ExternalId 복사` 이고 값은 들어가지 않는다. 창을 닫으면 지우고, 닫은 `pending` 계정은 `역할 ARN 입력` 의 이어서 하기 안내(ExternalId 는 다시 안 보여 줌)로 간다. 앱의 15초 요청 제한이 서버 처리보다 먼저 끝나면 값을 받지 못한다 (이어서 하기로 대신한다).
- **연결 해제 확인**: 웹과 같은 논리(다른 블록이 쓰면 이 블록에서만 떼고, 아니면 확인 뒤 지운다)이고 확인 문구도 같다 (`그대로 두기`가 먼저, AWS 스택·GitHub 앱 설치는 지워지지 않는다고 적음). 어느 블록도 쓰지 않는 AWS 계정은 한 블록에 고른 뒤에야 해제할 수 있다. GitHub `연결 해제` 는 웹처럼 확인 없이 바로 블록에서만 뗀다 (GitHub 앱 설치는 그대로).
- **새 배포 화면**: `계정 연결` 에서 `선택`한 블록(저장된 번호가 쓸 수 있는 블록일 때) 아니면 쓸 수 있는 블록이 하나뿐일 때 그것을 미리 고르고 레포 목록을 불러온다 (웹은 하나뿐이면 저장된 번호보다 앞선다. 쓸 수 있는 블록이 하나면 결과가 같다). 쓸 수 있는 연결이 없으면 `계정 연결 열기` 안내(앱에만 있는 문구). `계정 연결` 에 다녀와 다시 보이면 연결 목록을 다시 읽는다 - 직접 고른 것은 덮지 않고, 고른 블록이 사라지거나 쓸 수 없게 되면 선택과 분석 결과를 비우며, 바뀐 것이 없으면 분석 결과를 그대로 둔다.
- **로그**: 가로 스크롤 대신 줄바꿈, `FlatList`가 아니라 `ScrollView`(최대 500줄). 맨 아래에 있을 때만 따라 내려간다.
- **확인 창**: 앱은 `Alert.alert`(취소가 먼저), 웹 번들은 브라우저 `confirm`이라 버튼 글자를 못 바꿔 본문에 `[확인] 멈춤 / [취소] 그대로 두기`처럼 적는다.
- **키보드**: 스크롤 되는 폼 + `keyboardShouldPersistTaps`, iOS는 `automaticallyAdjustKeyboardInsets`, 안드로이드는 스크롤을 `KeyboardAvoidingView`(`behavior="height"`)로 감싼다. 안드로이드 처리는 구현만 했고 **기기에서는 확인하지 못했다**. 두 플랫폼 모두 기기 확인 전이다.
- **아래 여백**: 목록·새 배포·상세의 스크롤 끝에 하단 안전 영역(`insets.bottom`)을 더한다.
- **고정폭 글꼴**: `monoFont`(iOS Menlo, 그 외 monospace)를 모든 곳(환경변수 카드, 로그, 해설 원문, Dockerfile, 앱 폴더)에서 쓴다.
- **환경변수 종류 선택**: 웹의 `<select>` 대신 칩 다섯 개. 그룹 접기는 눌러서 여는 머리줄.
- **뒤로 가기**: 웹의 `← 목록` 링크 대신 상단 헤더의 뒤로 가기. 제목은 `배포 #번호`.
- **터치 크기**: 앱 쪽 버튼·입력·선택 줄은 44pt 이상으로 만들고 웹 번들로 쟀다. 헤더 뒤로 가기는 웹 번들에서 30×30으로 나왔다(내비게이션 기본 헤더, 기기에서 미확인).
- **다크 모드**: 시스템 설정을 따른다. 색은 `app/src/theme.js`의 토큰이고, 터미널 색은 라이트·다크 모두 어두운 바탕용 값이다.

### 인시던트·알림·설정 (D2)

**웹 대응은 계획 E 에서 만들었다** (위 "4. 운영 화면", 웹과 다른 점 포함). 아래는 앱 쪽 설명이다. 서버 필드 이름(`i_id`, `open_incident_id`, `open_incident_status`, `health_state`, `auto_recover`, `explain.fix_where` ...)과 상태·종류 값은 백엔드와 같고 `app/src/ops/constants.js` 한 곳에 있다 (`incident.status`: `open|recovering|resolved|needs_action`).

- **목록 머리줄 (웹과 다름)**: 머리에는 알림 종 + `＋ 새 배포` 만 둔다. 종은 44×44, 안 읽은 알림이 있으면 숫자 배지(99 넘으면 `99+`), 접근성 라벨 `알림 {n}개 읽지 않음`/`알림`. `계정 연결`·`알림 설정` 은 머리 밑 줄의 칩(44pt 이상)이다 (머리에 다 담기지 않아서 옮겼다). 종을 누르면 `/notifications`.
- **문제 배너**: 끝나지 않은 인시던트(`open_incident_id` 가 있는)가 있는 배포마다 목록 위에 한 줄 `{레포}에 문제가 있습니다 · 자동 복구 중`. 인시던트가 `needs_action` 이거나 그 배포의 `auto_recover` 가 꺼져 있으면 `... · 확인이 필요합니다` (`open_incident_status` 를 모르는 옛 서버는 `auto_recover` 만 본다). 누르면 `/incidents/{id}`. `running` 카드의 오른쪽에 헬스 점(초록·빨강·회색, `health_state`). 배포 상세에는 인시던트 카드(한 줄 요약 + `자세히 보기`).
- **인시던트 상세** (S-13): 요약 + 상태 배지(감지됨·복구 중·해결됨·확인 필요), 배포 번호·종류·감지(·해결) 시각, `원인`(없으면 "아직 원인을 확인하지 못했습니다"), `고칠 곳`(고정폭, 선택·복사 가능, 긴 ARN 도 줄바꿈), `해야 할 일`, `마법사가 한 일` 세로 타임라인(자동 재시작·되돌리기와 결과는 **읽기 전용 기록**), `헬스체크 이력` 최근 24시간 막대(15분 칸, `최근 24시간 정상 N%`). `open`·`recovering` 인 동안 5초마다 갱신하고, `resolved`·`needs_action` 이 되면 멈춘다 (앱이 백그라운드면 멈춤). 불러오기가 실패하면 404 일 때 멈추고, 그 밖의 실패는 5→10→20→30초로 늘려 가며 다시 시도한다. 삭제된 배포·없는 인시던트는 한국어 안내 + `돌아가기`. `needs_action` 이면 `다시 배포`·`멈춤`(확인 창, 안전한 `그대로 두기` 먼저)·`그대로 두기`; 동작 뒤에는 `배포 보기` 만 남는다. 앱은 자동 조치를 하지 않는다 (CLAUDE.md 규칙 3: 서버가 하는 재시작·되돌리기만 있고 앱의 모든 변경은 사용자가 누른 버튼이다).
- **배포 설정** (S-14): `새 커밋이 오면 자동 재배포`, `문제가 생기면 자동 복구` 스위치 줄(56pt 이상, 줄 전체가 눌림 대상, 라벨에 `배포 #번호`). 누르면 바로 저장(바꾼 항목만 `PATCH`), 실패하면 그 스위치만 되돌리고 서버 문구를 보인다. 자동 복구 설명에 "재시작과 이전 버전으로 되돌리기만 합니다. 삭제나 사양 변경은 직접 확인한 뒤에만 합니다." 가 들어 있다. 배포 상세의 `설정` 버튼(`deleting`·`deleted` 가 아니면 보임)으로 들어간다.
- **알림 목록** (S-12): 안 읽은 알림은 굵게 + 점, 아이콘·종류·시각, 누르면 읽음 처리 후 인시던트(`incident_*` 종류)나 배포 화면으로 이동. `모두 읽음`, `더 보기`(가장 오래된 `n_id` 를 `after` 로), 비었을 때 `새 알림이 없습니다`, 불러오기 실패 시 `다시 시도`. 목록에서 읽음 처리가 실패하면 되돌리고 맨 위에 안내.
- **알림 설정** (S-15 알림 부분, S-17): 메일 스위치("서버에 메일 설정이 있을 때만 보내집니다"), 푸시 스위치("이 설정은 모든 기기에 적용됩니다"), 종류 6개 스위치("끈 종류는 앱 안 알림 목록에도 남지 않습니다" 안내 한 줄). 푸시는 안내 글을 읽고 `알림 켜기` 를 누른 뒤에만 OS 권한을 묻는다 (앱 시작·화면 열림에는 묻지 않음). 푸시 스위치는 이 기기가 준비됐을 때만 켜져 보인다. 거부됐으면 OS 설정에서 켜는 방법을 안내한다. `running` 배포의 상세에는 이 기기의 알림 권한이 아직 정해지지 않았을 때 안내 카드가 뜬다 (`나중에` 로 닫으면 다시 안 뜸).
- **알림을 눌렀을 때**: `data.link` 가 `deploywizard://deploys/{n}`·`deploywizard://incidents/{n}` 일 때만 그 화면으로 가고 그 밖의 값은 무시한다.

플랫폼 메모:
- **웹 번들**: 푸시를 지원하지 않는다 (`expo-notifications` 를 번들에 넣지 않음). 푸시 줄에 "이 환경(웹, 알림을 지원하지 않는 기기)에서는 푸시 알림을 쓸 수 없습니다. 앱 안 알림 목록은 그대로 쓸 수 있습니다." 안내만 보이고 `알림 켜기` 는 없다. 확인 창은 브라우저 `confirm` 이다.
- **Expo Go(안드로이드)**: SDK 53 부터 원격 푸시가 안 된다 (개발 빌드 필요). 푸시는 개발 빌드나 실제 기기 빌드에서만 시험할 수 있다. **EAS 프로젝트 id 가 아직 없어서** 어느 빌드든 푸시 상태는 `no_project` 이고 "스토어 빌드 준비(EAS 프로젝트 연결)가 필요합니다" 안내가 나온다. 푸시는 실제로 돌려 보지 못했다.
- 터치 크기: 새 화면의 버튼·스위치 줄·칩은 44pt 이상이고 웹 번들로 쟀다. 헤더 뒤로 가기만 30×30 이다 (기본 헤더, 기기에서 미확인). 가로 넘침 없음(390).

확인은 jest(목), 웹 번들 내보내기, `/api/**` 를 모의한 Playwright(390×844 라이트·다크)뿐이다. 실제 기기·실제 백엔드·실제 푸시 발송으로는 돌려 보지 않았다.

앱에 없는 화면: 인시던트 목록, 로그인, 운영 에이전트. 딥링크 복귀와 웹의 "PC에서 이어서 하기" 링크도 없다.

계정 연결 화면은 실제 기기·에뮬레이터, 실제 백엔드, 실제 AWS·GitHub 로 돌려 보지 않았다. 웹 번들(390×844 라이트·다크, `/api/**` 모의)과 jest 로만 확인했다. `Modal` 안의 키보드와 안전 영역, 외부 브라우저 왕복 때의 `AppState` 순서는 기기 확인 전이다.

## 디자인 토큰

`shared/ui/styles.css`의 `:root`에 정의. 컴포넌트에 색을 직접 쓰지 않는다. `prefers-color-scheme: dark`에서 같은 이름으로 재정의된다.

| 토큰 | 용도 |
|------|------|
| `--bg` `--surface` `--surface-2` `--border` | 바탕, 카드, 옅은 면, 선 |
| `--text` `--muted` | 본문, 보조 글자 |
| `--accent` `--accent-text` | 주 버튼, 링크, 진행 중 |
| `--ok` `--ok-bg` | 정상 |
| `--warn` `--warn-bg` | 실험 지원, 자가수정 |
| `--err` `--err-bg` | 실패, 삭제 |
| `--term-bg` `--term-text` | 터미널 (두 테마 모두 어둡게) |
| `--radius` `--mono` | 모서리, 고정폭 글꼴 |

상태 배지: `running` → ok · `failed` → err · 진행 중 → accent(점 깜빡임) · 그 외 → muted.
