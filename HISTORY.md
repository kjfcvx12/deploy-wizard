### Windows note
`.venv/Scripts/python.exe -m uvicorn ...` spawns as 2 PIDs (a venv launcher + the base miniforge interpreter it wraps) with the same start second; only the 2nd one actually binds the port (`netstat -ano | grep LISTENING` to find it, not the PID you launched). Confirmed harmless — new-code artifacts (the `/issues` route, new resume log strings) proved it was running current code, not a stale process.

### Gotchas (2026-09-22, M6)
- `no such column: deploys.X` on server start after adding model columns — `create_all` never alters existing tables. Delete `data/wizard.db` (disposable local dev data, no migrations yet) and restart.
- `shutil.rmtree(dest, ignore_errors=True)` on Windows silently leaves git's read-only pack files behind → next clone into the same dir fails with "already exists and is not an empty directory". Fixed in `services_repo_clone` with an `onexc` handler that clears the read-only bit first (Python 3.12+ API — this venv is 3.12.14).
- `sqlalchemy.exc.OperationalError: database is locked` intermittently in pytest, only in test files that create real `asyncio.Task`s that outlive a test function (e.g. debounce timers) — pytest-asyncio's per-test event loop clashes with the single module-level `async_engine`/connection pool shared across tests. Fix: give that test file a **module-scoped** event loop (`pytestmark = pytest.mark.asyncio(loop_scope="module")` + matching `loop_scope="module"` on its fixtures) instead of trying to perfectly cancel+await every task at teardown.

## Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-09-21 | Feature folders (`features/<f>/` = .py + `ui/`), no back/front split | one change touches one folder |
| 2026-09-21 | SQLite default, `DB_URL` swappable | solo tool, zero setup |
| 2026-09-21 | Rule-based fallback when LLM unavailable | official languages must always finish |
| 2026-09-21 | Never auto-delete AWS resources on failure | spec ch.03: only automatic action is rollback |
| 2026-09-21 | Saved records in terse English; chat/comments/UI in Korean | token cost |
| 2026-09-22 | M6 scope: full plan (AssumeRole+GitHub App+webhook/poll) in one design pass, no PAT stopgap | product owner chose "M6 all at once"; PAT would be throwaway work since the spec's own target for M6 is GitHub App |
| 2026-09-22 | M6 secrets: app-level Fernet encryption, not AWS Secrets Manager | zero cost, no new AWS service, easy to upgrade later; matches solo-project cost-consciousness (05장) |
| 2026-10-06 | Dev-account credentials via `aws login` (console OAuth), not `aws configure` access keys | no long-lived keys on disk; AWS has no third-party OAuth, so M6 cross-account stays AssumeRole+ExternalId |
| 2026-10-07 | End of session deletes ECR images by default, not just services | owner wants every cost stopped, including small storage fees; records stay so `[다시 켜기]` rebuilds. `--keep-images` exists for a faster restart |
| 2026-10-07 | Guide presents GitHub "All repositories" as the connect-once choice (was: recommend selected repos) | owner's product flow is "connect once, then paste any repo URL"; access is read-only either way; selected repos stays available and explained |
| 2026-10-07 | Deploy target stays AWS only; Azure / Google Cloud not pursued | owner's rationale: largest cloud by market share (owner's figures: AWS ~28%, Azure ~20%, Google Cloud ~15%; source not recorded), so the most users already have an account to connect |
